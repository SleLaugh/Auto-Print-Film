# 请求级窗位与 DICOM 显示设计

部位取景策略：普通 MPR 可配置 `framing_policy`，默认仅髋骨冠状位启用 `selected_region`、每侧 `5 mm`。
任意正数占比 p 的共同视野为“整组原标签包络尺寸+两侧余量”除以 `p/100`，固定面内中心、整组共用倍率。
100优先完整显示所选部位；占比降低时从未预裁的原 CT 逐渐显示更大外围，不保证80已露出全部皮肤，超源处保留正常无数据背景。
本文完整人体保护、`skin_edge` 及髋部逐层合法中心说明均指未启用该策略的计划；0/null和肺部正式策略保持原行为。字段、覆盖边界及诊断见[整组取景设计](../reconstruction/2026-10-08-整组居中与FillPercent取景设计.md)。

2026-10-08 补录 `d8c4e3b`；2026-10-16 更新为传入窗宽窗位同时决定显示灰度和 DICOM 窗位标签。

## 输入与优先级

每项 plane_configs 的 `WindowPresets` 仍是名称列表。
请求顶层 `window_presets` 定义本次任务的覆盖表；CLI 使用 `--window_presets`：

```json
[{"Name":"骨窗","windowWidth":2500,"windowLevel":400}]
```

按名称先查本次覆盖表，再回退 src/config/window_presets.json。
可覆盖默认名称，也可定义新名称；覆盖表中未被任何 plane_configs 引用的条目不会自动生成成片。
作用域为整个请求，同名窗位在各计划中使用相同覆盖值，不修改默认 JSON 或全局预设缓存。
请求字典兼容顶层 WindowPresets；序列化统一输出非空的 window_presets。

外部条目规范字段为 Name/windowWidth/windowLevel；解析器还接受
name/window_width/window_center。名称必须非空且不重复，窗宽为正有限数字，
窗位为有限数字，布尔值非法。默认表及 Python 请求实体同样拒绝非有限值和超大整数。
未知且未覆盖的窗位名称仍拒绝。

## 正式切片的像素与窗位

先完成 HU 重采样及各模式共同倍率、实际面内中心的取景，`write_ct_dicom` 接收未取整的重建 HU，
内部按实际所选窗宽窗位调用 `apply_window_to_image`，生成 uint16 灰度：

`gray = round(clip((HU - (level - width/2)) / width, 0, 1) * 65535)`

窗口算术使用 float64，即使输入 HU 为 float32，也不把传入的小数窗位和窗宽降精度。
这里不先把插值或厚层平均得到的小数 HU 取整；窗内只进行 16 位灰度量化，
窗外数值则按所选窗口截断。输出是用于出片的派生显示 CT，不能恢复窗外 HU，
也不承诺通过重新调窗恢复原始数据；定量数据应读取原始 CT 序列。

GDCM 写盘时使用恒等 Rescale，保证灰度字节不变；写盘后补入以下标签：

- `RescaleSlope = width / 65535`
- `RescaleIntercept = level - width/2`
- `RescaleType = HU`（对应窗口内量化后的 HU，窗外已截断）
- `WindowWidth = width`、`WindowCenter = level`
- `VOILUTFunction = LINEAR_EXACT`

因此查看器先应用 Rescale，再按同一实际窗宽窗位执行 `LINEAR_EXACT`，
得到的归一化显示值为 `gray / 65535`，与程序生成的窗化灰度一致。
请求覆盖值同时决定灰度与标签；只有本次未覆盖的名称才回退默认配置。

同计划各窗共用未窗化的重建 HU 和采样几何，分别生成灰度并写入各自窗位标签和序列标识。
SeriesDescription 继续保留所选窗名及窗宽窗位用于识别。

## 定位图与调试 PNG

`Localizer.dcm` 属于带定位线的合成显示数据。它仍将背景按对应窗口映射为
uint16 灰度，再按共享的亚像素覆盖率叠加白线：

`gray = round(clip((HU - (level - width/2)) / width, 0, 1) * 65535)`

定位图在 GDCM 写出后设置以下标签，再发布正式文件：

- `RescaleSlope = width / 65535`
- `RescaleIntercept = level - width/2`
- `RescaleType = US`（未指定单位）
- `WindowWidth = width`、`WindowCenter = level`
- `VOILUTFunction = LINEAR_EXACT`

这样保留现有背景和白线效果，同时让查看器显示实际选用的窗宽窗位。
Rescale 换算结果包含已经窗化裁剪的背景和人工定位线，不能作为可定量 HU 使用。
调试 `Localizer.png` 继续从相同窗化背景和覆盖率生成，保持原有灰度及红线效果。
旧输出不会自动改写，必须重新运行切割才能更新。

## 与查看器的边界

FillPercent 控制目标在输出图像中的占比，查看器控制图像相对屏幕的缩放。
图像变大不保证查看器打开就铺满屏幕；物理视野、三视图联动和适配窗口都影响观感。

肺/髋普通 MPR 的 80 等 `0<FillPercent<100` 保持原目标中心与公式：肺部由最大实际目标
bbox 面积参考层确定整组平移，髋骨按当前厚层目标居中；共同视野取标签目标尺寸/比例与
既定中心下人体保护尺寸的逐轴较大值。100 则独立采用人体与目标并集的紧致视野，
不再与旧标签对称视野取较大值：肺部给所有层追加同一个包络中心校正，髋骨共同视野取
各层并集尺寸最大值，仅把原中心超出合法区间的坐标移入区间，合法坐标不动。
100 的目标部位可偏离绝对正中，肺部肩臂仍可决定整组宽度，不逐层拉满小截面。
正数每源提取一次完整人体支持，按实际源几何、厚层采样和 `2 mm` 余量保护皮肤、肋骨、
骶尾骨、肩臂及双腿；外部空气与可可靠分离薄床板不限制倍率。人体不参与标签尺寸或
肺参考层选择。人体不可识别的源层局部回退完整源盒，不能可靠分离的设备保守保留。
同组各层各窗共用倍率、Rows、Columns 和 PixelSpacing，保留矩阵奇偶性，不执行后续上下 ROI。
100 可校正面内中心，不能宣称相对源图只作整数 ROI 或保持原目标网格相位；DICOM 逐张记录
实际中心、原点和方向。原计划法向、层位、范围、厚度、间距、张数和定位图保持不变。
肺/髋普通 MPR 的 0/null/省略同样保源、不做上下 ROI，保基础间距、scale=1 和整组中心，
必要时扩大共同矩阵并保持奇偶性；查看器 fit 后的屏幕大小仍可能变化。
其余适用平面 MPR 和椎间隙在 HU 采样后逐张裁去首尾完全无源支持行，以裁后整幅图居中，
有效内容、像素比例和左右取景余量保留；0/null/省略同样执行，CPR 和 Localizer 不裁。
这一步消除图像内部的上下无数据带，不删除真实空气或窗化黑色；外部查看器仍可因
显示格宽高比和 fit 设置添加留白，后端无法在完整保留内容和比例时保证任意格子四边铺满。

取景后空气背景减少会改变像素最小值和直方图。
查看器若自动按当前数据范围调对比度，可能让同名骨窗看起来更暗。
对照输出应固定相同的实际窗宽窗位，并在相同物理位置核对显示灰度和 DICOM 标签；
定量 HU 应回到原始 CT 序列核对，不能从窗外已截断的正式切片或带合成定位线的定位图恢复。
程序不控制 ITK-SNAP 的自动对比度、默认屏幕缩放或 UI 黑边。
