# 预处理与分割缓存设计

本文于 2026-10-08 补录，依据提交 `a3f1f80`、`6faf84e` 及当前实现；描述已实现行为，不是待实施计划。
2026-10-26 更新同序列并发、跨进程缓存写锁和私有工作目录边界。

## 请求与目录所有权

CLI 使用 `-c/--cache_dir`；Python 属性和请求字典均为 `cache_dir`，不传或为空时不启用外部持久缓存。
`-o/output_dir` 是可重建的本次任务专用目录；启动清理保留 `log/`，不保留旧业务输出。
缓存应为独立、按输入病例/序列隔离的目录，不能等于输出目录或位于输出目录内；预检会拒绝这两种关系。

| 产物 | 指定 cache_dir | 未指定 cache_dir |
| --- | --- | --- |
| 第一阶段原始体数据 | `<cache>/nifti/raw_0000.nii.gz` | `<output>/nifti/raw_0000.nii.gz` |
| 第一阶段调试元数据 | `<cache>/metadata/dicom_metadata.json` | `<output>/metadata/dicom_metadata.json` |
| 第二阶段分割 | `<cache>/<model_id>/segmentation/seg.nii.gz` | `<output>/segmentation/seg.nii.gz` |
| 分割模型标记 | 与 seg 同目录的 `model.json` | 与 seg 同目录的 `model.json` |

三至八阶段仍在本次输出目录工作。校正候选、定位、取景与 DICOM 成片不是这套缓存的复用对象；
改变 FillPercent、窗位或切片参数仍需重新规划和重建，不能把缓存理解成整任务断点续跑。
同一原始序列的多个任务可共用同一 cache_dir，但必须使用不同 output_dir。
C# 按规范化输出路径互斥，并原子检查全局 `MaxConcurrentCount`、序列占用、启动和登记进程。
同序列首任务结束前只运行一个完整任务；已有“已切割”或“切割失败”任务且其输出目录
已无活进程后，若正式 raw 和至少一个模型的正式 seg 已生成，就放行剩余任务并发。
存在模型标记时要求匹配模型目录，兼容无标记的历史缓存；临时工作目录不算缓存。
缺体素等后续失败不阻止缓存复用，没有正式缓存时继续由一个待处理任务接替。
此处只判断序列是否已生成至少一份分割，不复制请求模型匹配，不保证其他模型也已缓存。
直接使用 CLI 的调用方也须保证输出目录独占。

## 命中与失效

1. 第一阶段发现 `raw_0000.nii.gz` 存在即复用，仍从输入 DICOM 读取可继承的源标签。
   缓存命中不要求调试元数据存在。
2. 第二阶段先按部位、检查类型和扫描厚度匹配模型，再寻找该模型目录。
3. `seg.nii.gz` 存在且 `model.json` 中的 model_id 匹配则复用。
   无模型标记的历史分割也允许只读复用，不在命中时补写标记。
4. 模型标记不匹配或读取失败，不复用；先在私有工作目录推理成功，再清理旧分割及
   附属文件并发布新结果。不能把自有资料放入这个模型的 segmentation 子目录。
5. 缓存未命中时写入上述固定位置，不另建按日期命名的缓存。

## 并发写入与发布

- 第一阶段缺失缓存时获取 `<cache>/.locks/preprocessing.lock`，持锁后重新检查命中。
  一个进程在私有工作目录完成 DICOM 转换，最后原子发布 `raw_0000.nii.gz`；
  等待进程随后复用，已完成缓存只读读取，不重复改写。
- 第二阶段使用 `<cache>/.locks/segmentation-<model_id>.lock`。同序列同模型只有一个
  写入者，等待者拿锁后复查并复用；不同模型目录和锁相互独立，可分别执行推理。
  每次尝试使用新的私有工作目录，标记及其他推理产物完成后最后发布 `seg.nii.gz`，
  避免半成品被当成命中。未指定 cache_dir 时同样的保护位于任务 output_dir 内。
- `.locks` 中的锁文件必须保留，删除锁文件可能使同一路径出现两个锁拥有者。
  私有工作目录带应用标记和独立租约；POSIX 推理子进程继承租约，即使父进程退出也
  继续保护仍在写入的目录。回收只处理标记有效且能取得租约的已遗留目录，跳过活动目录、
  符号链接及不带标记的历史目录；Windows 对遗留目录回收保持保守。
- 第三至八阶段只写本次 output_dir，可与其他同序列任务同时执行；共享缓存不保存
  校正候选或正式切片。缓存锁等待不计入 Python 单次 nnUNet 推理时限，C# 不新增任务超时。

## 目前的安全边界

当前没有输入 DICOM 内容哈希、模型权重版本、configuration/fold 指纹。
不同病例不得共享同一 cache_dir；替换输入数据或模型权重后应使用新缓存目录，或由操作者明确清理旧缓存。
跨进程写锁保护同序列首次生成与复用，不提供输入或权重变化后的自动失效，也不保证识别任意缓存损坏。
不要在任务仍在读取或写入时手动删除、替换缓存和锁文件。
缓存命中也不会跳过默认预检中的 nnUNet 可执行文件与模型目录检查。
