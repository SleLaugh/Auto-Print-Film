# DICOM 数字命名与定位图设计

肺部、髋骨三状位普通 MPR 默认按所选标签取景，每侧余量 `5 mm`。
肺部、髋骨全部普通MPR状位统一使用原标签整组包络中心，整组固定中心、倍率与矩阵。
保留第六阶段原CT投影画框及物理宽高比，100容纳所选标签+余量；70、50同心向四周扩展视野。
0/null/省略、其他部位、CPR、椎间隙与定位图保留原规则。详见[整组取景设计](../reconstruction/2026-10-08-整组居中与FillPercent取景设计.md)。

定位图背景的配置来源、参考点以及与 FillPercent 的隔离关系，见
[定位图状位配置与取景隔离设计](2026-10-08-定位图状位配置与取景隔离设计.md)。

## 正式切片

每个计划和窗位目录内的正式重建切片使用从 `1.dcm` 开始的纯数字文件名。
`InstanceNumber (0020,0013)` 同样从 1 开始连续递增，但文件名只是交付组织，
不能改变切片物理几何。

正式切片按实际窗宽窗位将未取整的重建 HU 映射为 uint16 灰度；GDCM 写盘后设置
`RescaleSlope=窗宽/65535`、`RescaleIntercept=窗位-窗宽/2`、`RescaleType=HU`，
`WindowWidth`、`WindowCenter` 写入实际预设值，`VOILUTFunction=LINEAR_EXACT`。
窗内存在 16 位灰度量化，窗外数值已截断；这是用于出片的派生显示 CT，定量数据应读取原始 CT 序列。

第八阶段只把完整文件名匹配正整数的 DICOM 当作正式切片，按数值顺序校验数量、
`InstanceNumber`、UID 和空间信息。正式切片必须满足：

- 文件名和 `InstanceNumber` 都从 1 连续递增，实际张数与第七阶段声明一致；
- 每个窗位只有一个 `SeriesInstanceUID`，每张图有唯一 `SOPInstanceUID`，同一任务
  的不同正式序列和定位图不能复用 Series/SOP UID；
- 同一任务只允许一个 `StudyInstanceUID`；
- `Rows`、`Columns` 和 `PixelSpacing` 有效，像素间距大于零；
- `ImagePositionPatient` 有 3 项，`ImageOrientationPatient` 有 6 项，后者的行列方向
  必须是正交单位向量；
- `SliceThickness`、`SpacingBetweenSlices` 大于零，并与第七阶段透传的计划层厚、
  层间距一致。

肺/髋正数普通MPR以所选标签整组投影包络加每侧 `5 mm` 为目标，整组固定中心、倍率和矩阵。
统一使用 `selected_region`、缺省group中心、`canvas=original`，不再逐层追随目标或选择肺参考层。
保留第六阶段原CT投影画框的Rows、Columns与基础像素纵横比，在原画框物理宽高比内等比适配目标。
100完整容纳所选标签及余量，70和50在同一组中心宽高同时扩为100的1/0.7、2倍。
直接从完整原CT采样，不预裁外围组织；不以完整人体限制倍率，目标框外皮肤、肋骨或骶尾结构允许越框。
所有层、占比及窗位共用固定矩阵，不执行逐张上下ROI；小截面和不限制适配的一轴仍可留空气。
不拉伸解剖、不将小目标逐张拉满；原切面、法向层位、范围、厚度、间距、张数和定位图不变。
肺/髋普通 MPR 的 0/null/省略同样保源、不做上下 ROI，保基础间距、scale=1 和整组中心，
必要时扩共同矩阵并保持奇偶性；组内跨窗几何仍一致。
除这些计划外，`plane_stack` MPR 和椎间隙
（含 0/null/省略）在 HU 采样后以 ROI 裁去首尾完全无源支持行，
保留有效像素、Columns、PixelSpacing 和网格相位，以裁后整幅图的物理中点居中；最终 Rows、
垂直视野和中心可逐层不同。ImagePositionPatient 按裁后原点真实记录，不能假定为固定面内原点的规则直角三维体。
面内平移不改变切平面、法向层位置、厚度或层间距，跨窗仍共用每张的实际几何。
CPR 和 Localizer 不执行上下裁空；整张无源支持的平面层保持原样并标记 `no_source_support`，
不能通过删除真实空气、按全组最短高度裁剪或补框来恢复共同 Rows。

## 定位图

每个窗位目录同时保存不编号的 `Localizer.dcm`。定位图以原始 CT 正交参考层或
脊柱深度曲面作为背景，绘制当前计划的定位线，并使用独立 Series UID。它不计入
正式切片数量。颈椎、胸椎、腰椎、脊柱矢状位 MPR/CPR 的冠状背景先在原 x/z 显示网格
沿 y(z) 采样；几何不足时回退单层，其余状位保持正交背景。所有背景在绘线前按
通用规则对粗显示轴做二维线性细化，保持固定参考点、方向和首末像素物理范围。

- `plane_stack` 按第六阶段真实平面位置、法向绘制无限平面与定位平面或曲面的交线，
  仅裁到底图显示边界，不按正式 MPR 视野裁线；
- `curved_stack` 按实际 CPR 采样路径的弧长采样投影全部有效 offset 中心线；新矢状位
  应先应用 `curve_projection_axis`，使用固定 AP 参考面内的冠状投影。冠状背景深度
  仍来自真实三维 `curve_points`，不使用采样投影替代；若计划未包含
  `offset=0`，定位图额外补画基准中心线。

参考显示状位和正交背景参考层由第六阶段计划中的 `localizer_plane`、
`localizer_reference` 决定。多个计划可以共享同一背景层，但仍分别叠加自己的
定位线；这两个字段及曲面背景优化不改变正式切片几何。曲面背景及腰椎共享选层规则见
`../reconstruction/2026-08-11-腰椎统一中心定位图设计.md`。
同一输入及计划下，切换 FillPercent 不改变 Localizer 的矩阵、像素间距、参考点、
背景取样或 MPR 线长；底图显示网格可独立细化，不随正式切片缩放、裁切或逐层移动。
原轴间距大于最细显示轴的两倍或大于 `2 mm` 时，该轴向
`min(最细显示轴间距, 1 mm)` 细化，再按真实 MPR 交线或 CPR 投影重画约一显示像素宽的
抗锯齿线。曲面背景保留原物理路径映射；仅插值二维背景，不增加解剖细节，
不做全体三维重采样，不改变正式切片的厚度、范围、FillPercent、间距或张数。

debug 模式在相同目录额外写 `Localizer.png`，非 debug 模式不产生 PNG。

定位图保留窗化背景与白线的 uint16 像素，在 GDCM 写出后设置
`RescaleSlope=窗宽/65535`、`RescaleIntercept=窗位-窗宽/2`，并写入实际窗宽窗位和
`LINEAR_EXACT`。`RescaleType=US` 表示未指定单位；这是合成显示数据，不能用于定量 HU 测量。
debug PNG 沿用原有窗化背景及红线显示。
曲面 Localizer 须在 DICOM 派生说明中注明曲面采样与非平面空间语义；其位置、方向
和间距只描述显示参考网格，不能把曲面背景当作普通原始冠状平面做精确三维联动。

## 写盘约束

正式切片和定位图均须经过 GDCM 串行保护入口。写盘后恢复第六阶段计划的
`ImagePositionPatient` 和 `ImageOrientationPatient`，避免二维定位图显示轴
覆盖真实患者物理方向。

同一计划的多套窗宽窗位仅改变 Localizer 的显示像素、显示标签、Series UID 和描述，不改变
空间几何。第七阶段必须在进入窗位线程前冻结原始 Localizer 的位置和方向，等正式
切片窗位任务全部完成后，再在主线程按窗串行写出定位图。四个窗的
`ImagePositionPatient`、`ImageOrientationPatient`、Rows 和 Columns 必须一致。
两项空间标签任一缺失时应直接失败，不能接受 GDCM 生成的二维默认值。

## 第八阶段发布门禁

第七阶段在每个输出摘要中透传 `geometry_type`、`slice_thickness` 和
`slice_spacing`。第八阶段使用 `pydicom` 直接读取磁盘最终文件，而不是相信内存中的
写出参数。除单序列校验外，同一计划各窗位还必须满足：

- 相同编号正式切片的 Rows、Columns、PixelSpacing、ImagePositionPatient、
  ImageOrientationPatient、SliceThickness 和 SpacingBetweenSlices 逐项一致；
- `Localizer.dcm` 存在、可读、`ImageType` 包含 `LOCALIZER`，使用独立 Series UID；
- 各窗 Localizer 的 Rows、Columns、PixelSpacing、ImagePositionPatient 和
  ImageOrientationPatient 逐项一致；
- 第七阶段的计划数、切片数、窗位图像数和目录归属与磁盘结果一致。

所有比较只覆盖客观 DICOM 协议和空间几何，不依据某个病例的灰度内容、椎体形态或
人工观感判定成功。校验通过后才在 `report.json` 中写入 `Success=true` 的切片结果。
校验失败时覆盖可能残留的成功报告，写入 `Success=false`、错误 `Message` 和空的
`PlaneList`，再抛出 `OUTPUT_VALIDATION_ERROR`；错误详情必须定位到计划、窗位、文件和
字段。debug 开启时先写 `metadata/处理报告_调试.json`，供失败排查。
