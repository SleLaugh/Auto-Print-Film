## 配置职责

`slice_part_config.json` 管理部位启用状态、模型区间、标签别名、定位区域、
允许切法、范围扩展和各切法的定位图状位。
`nnuNet_config.json` 管理 nnUNet 参数、模型路径与外部推理命令；
`logger_config.json` 管理日志与调试开关；
`window_presets.json` 是默认窗位表，本次请求可单独覆盖窗位。

`nnUNet_predict_command` 指定外部 nnUNet 命令路径，默认从 PATH 查找 `nnUNetv2_predict`。
`nnUNet_python` 是可选的外部 Python：留空时直接执行命令，指定时在该外部环境执行
nnUNet。应用依赖和可执行包均不包含 nnUNet 或 PyTorch。开发配置来自源码目录，
发布程序从其所在目录的 `src/config/` 读取 JSON；修改 JSON 后下一次启动生效。

`load_app_config` 合并配置并生成 AppConfig。
nnUNet 同一设置的优先级为显式 Python 配置、环境变量、默认配置、内建兜底；
日志与流水线段按显式值覆盖默认段，不应声称所有字段都可由任意同名环境变量覆盖。

`num_processes_preprocessing` / `num_processes_segmentation_export` 分别传给外部命令
`-npp` / `-nps`，默认均为 `1`，支持顶层 JSON、Python 的 `nnunet` 嵌套段及同名环境变量。
只接受正整数或整数文本，拒绝布尔值、浮点数、零和负数；单病例预处理原本实际已经是 1，
默认调整主要减少导出进程池的并发占用，不改变 TTA、滑窗步长或模型。
仓库 `logger_config.json` 默认开启独立错误日志，其他开关保持原值，显式配置仍优先。

`inference_timeout_seconds` 是单次外部推理时限，内建兜底为 1800 秒；
`inference_timeout_seconds_by_model` 是按模型 ID 覆盖的对象，内建兜底为空对象，
仓库 JSON 另外为肺部模型 `315` 设置 180 秒。时限必须为有限正数，模型键必须是
无前导零的正整数 ID 字符串。`inference_max_retries` 只允许整数 `0` 或 `1`，
默认 `1`，表示首次失败后最多额外重试一次。这些字段支持顶层 JSON、Python 的
`nnunet` 嵌套段及同名环境变量，遵守相同优先级；环境变量的模型映射使用 JSON 对象文本，
映射整体覆盖，显式 `{}` 可清空较低优先级的模型覆盖项。

监测循环从实时落盘的原始推理日志检测致命崩溃并检查单次时限，不同步转发原始进度到
控制台或 DebugLog。Linux 仅在确认本次进程组清理后，对超时、原生崩溃、信号终止或
后台 worker 异常退出使用新临时目录重试；模型缺失等明确配置错误不重试。
时限不含缓存锁等待和后续重建，C# 不增加超时或重试判断。
完整 stdout/stderr 分别保存到任务 `log/nnunet-*.stdout.log` 和 `log/nnunet-*.stderr.log`，
ErrorLog 仅记录命令及每个输出流末尾最多 64 KiB；收集诊断时应保留两份原始日志。

Worker 的 `MaxConcurrentCount` 限制全局在途任务数，与规范化输出目录互斥在启动、登记
临界区内共同执行；同一序列可以启动多个不同输出目录的任务。Python 的缓存写锁按
预处理根目录、分割根目录与模型 ID 隔离，同模型等待后复用，不同模型可分别推理，
第三至八阶段在各自输出目录并行。缓存锁等待不受单次推理时限限制。
并发规则见[批量执行设计](2026-10-08-批量执行与配置透传设计.md)，缓存发布及租约规则见
[缓存设计](2026-10-08-预处理与分割缓存设计.md)。

布尔项接受 bool 或字符串 true/false（忽略大小写及前后空白），不使用
`bool("false")`，其他类型/字符串明确报错。
统一部位配置严格检查未知字段、标签引用、未使用区域、模型区间重叠以及切法/区域类型。
每项正式切法规则必须提供合法且不同于重建状位的 localizer_plane。

## 统一部位配置和模型选择

顶层固定 `schema_version=1`，包含 `label_aliases`、`slice_parts`。
各部位包含 `enabled`、`model_rules`、`localization`、`slice_rules`；
启用部位必须同时具有模型、定位区域和切法规则。枚举中存在某个名称不代表能力已启用。

模型由外部 `SlicePart`、`StudyType`、`ScanThickness` 共同确定，不按结果目录名或
输出 `SliceThickness` 推断。`model_rules.<检查类型>` 中每项使用
`scan_thickness_range_mm.min/max` 闭区间匹配，指向正整数 `model_id`，可带
`configuration`、`fold`、`plans`。闭区间连公共端点也不能重叠；不命中则报错，不选最近档位。
扫描厚度允许非负有限值，包括 0，但 0 仍须匹配显式模型区间，不代表自动读取 DICOM。

命中规则后，三个可选字段分别覆盖 `nnuNet_config.json` 中的 `_configuration`、
`_fold`、`_plans`；未填写的字段各自继承全局默认值，不要求整组填写。仓库默认值为
`3d_fullres`、`0`、`nnUNetPlans`。自定义规则示例：`model_id: 123` 可以指定
`configuration: 3d_lowres`、`fold: all`、`plans: nnUNetPlans_Custom`；示例中的模型 ID
和计划名称应替换为实际部署值。仅填写 `model_id` 时，三项均使用全局默认值；只填写
`configuration` 时，`fold` 和 `plans` 仍继承默认值。
`plans` 对应 nnUNet 的 `-p` 训练计划名称，必须是合法非空名称；省略表示继承，
显式空字符串或 `null` 不作为继承写法。该字段不修改模型目录里的 `plans.json`。

`localization.regions` 用具名区域和 `type/start_label/end_label` 描述范围；
`slice_rules.<状位>.<SliceType>.regions` 引用这些区域，并给出首尾扩展和定位图状位。
引用必须存在，未使用区域也会报错；MPR/CPR 的整体区域与椎间区域类型不能混用。
支持 CPR 必须同时提供 `localization.spine_cpr`；未启用 CPR 切法时不能残留该配置。
标签短名通过顶层 `label_aliases` 展开，一个标准标签不能被多个短名重复占用。

能力表、分割选模、定位和规划均读取该统一配置，避免维护多份互相漂移的部位规则。
外部字段和请求示例见[状位配置请求](2026-07-08-状位配置请求设计.md)。

## 预检和运行时校验分层

1. 请求校验负责采样参数、窗位、FillPercent 等输入契约。
2. 能力预检确认部位/检查类型/状位/切法受支持。
3. 目录和依赖预检检查输入输出边界、缓存位置、nnUNet 命令与模型目录。
4. 规划及采样阶段校验几何条件；配置合法不等于某个病例一定具备所需标签。
5. 第八阶段读取最终 DICOM 校验后发布成功报告。

不能把配置校验、DICOM 发布门禁或 CI 单元测试中的任一项描述成替代全部检查。

## CI 与本地复现

`.github/workflows/ci.yml` 在 push/pull_request 上测试 Python 3.10、3.11，
安装 requirements-dev.txt 后依次运行：

```bash
python -m compileall -q main.py src scripts tests
python -m ruff check dev main.py src tests scripts
python -m pytest -q
```

批量脚本另用 `bash -n scripts/batch_test_plan.sh` 检查语法。
本地 `scripts/test.sh` 和 `scripts/test.ps1` 也统一使用项目 `.venv` 运行 pytest，
运行前安装 `requirements-dev.txt`。不再用 `unittest discover`，避免遗漏 pytest 函数式
发布测试。构建产物另由 `dev build` 验证移动运行、外置配置及基础影像依赖。
CI 的通过不等于真实 nnUNet/GPU 推理或 ITK-SNAP 显示验证已执行。
本机缺少某个校验工具时应如实说明，不能将语法检查写成静态检查全通过。
