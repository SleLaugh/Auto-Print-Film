# 横矢冠三状位切片总览设计

## 目标

调试模式下，把阶段四目前只为横状位生成的切片总览扩展到横状位、矢状位、
冠状位。三个状位必须各自生成普通检查网格和原始图像网格文件，不能把不同
状位混在同一个 NIfTI 中。

本次只扩展零角度直线计划的调试总览，不修改切片规划、MPR、窗位处理或交付
目录，不实现带角度总览。

## 输出文件

当整切请求同时包含横、矢、冠三个状位时，阶段四在 `metadata` 下生成：

```text
切片总览_横_整.nii.gz
切片总览_矢_整.nii.gz
切片总览_冠_整.nii.gz
切片原始网格总览_横_整.nii.gz
切片原始网格总览_矢_整.nii.gz
切片原始网格总览_冠_整.nii.gz
```

只请求部分状位时，只生成对应状位的文件。区间切继续使用既有后缀规则，
例如 `切片原始网格总览_横_区.nii.gz`。

## 生成流程

1. 按计划中的 `plane` 字段把 plans 分成横状位、矢状位、冠状位三组。
2. 每组创建一份原始参考网格 overlay，尺寸、spacing、origin、direction 与
   `seg_for_reconstruction_path` 指向的图像保持一致。
3. 每组再创建一份均匀检查网格 overlay，只把当前状位的法向输入轴细化为
   `0.5 mm`：横状位细化 Z，矢状位细化 X，冠状位细化 Y。
4. 在该状位固定的正交观察层上，绘制每张切片的中心线和层厚覆盖带。
5. 每个文件只包含当前状位的计划，不绘制其他状位。

## 三状位索引规则

| 输出状位 | 切片堆叠轴 | 总览固定轴 | 总览线延伸轴 | 普通总览细化轴 |
| --- | --- | --- | --- | --- |
| 横状位 | Z | X | Y | Z |
| 矢状位 | X | Y | Z | X |
| 冠状位 | Y | X | Z | Y |

第一版按当前默认零角度直线坐标系绘制。以后支持带角度时，应另行把绘制逻辑
升级为物理方向投影，不能把本次轴对齐规则误当成任意角度实现。

## 结果字段兼容

阶段四新增两个按状位保存路径的字典：

```json
{
  "debug_slice_plan_overview_paths": {
    "横状位": "...",
    "矢状位": "...",
    "冠状位": "..."
  },
  "debug_slice_plan_native_overview_paths": {
    "横状位": "...",
    "矢状位": "...",
    "冠状位": "..."
  }
}
```

保留原来的 `debug_slice_plan_overview_overlay_path` 和
`debug_slice_plan_native_overview_overlay_path`。存在横状位时，旧字段继续指向
横状位文件；不存在横状位时，指向请求顺序中的第一个可用状位文件。

`slice_plans.json` 同时写入新旧字段，避免现有调试工具立即失效。

## 错误和空输入处理

- 缺少或找不到 `seg_for_reconstruction_path` 时，所有总览路径保持为空。
- 某个状位没有计划时，不为该状位生成空文件。
- 某个计划没有 slices 或有效范围时，跳过绘制，但不影响其他计划和状位。
- 不识别的 plane 不生成总览，由现有规划和能力校验负责阻止异常请求。

## 测试验收

- 横、矢、冠整切请求生成六个独立 NIfTI 文件。
- 三个原始网格总览的尺寸和图像信息与参考图一致。
- 三个普通总览分别只在 Z、X、Y 法向轴使用 `0.5 mm` spacing，并保持相同
  物理覆盖范围。
- 每个文件包含对应状位的中心线和层厚覆盖带，不是全零图像。
- 旧的横状位单路径字段和值保持兼容。
- 阶段四、阶段五及完整测试集通过，且不执行 git commit。
