## 结论

- 默认主链固定为前处理、分割、空间校正、标签定位、解剖分析、切片规划、图像重建、
  校验与报告八个阶段。
- 原第三阶段职责拆为第三至第五阶段；切片规划统一为第六阶段 `PlanningStage`，
  `MappingStage`、`MappingStageResult`、`stage_mapping.py` 和 `mapping` 结果键已删除。
- 当前文档按八阶段职责重写；历史六阶段说明只保留在 `archive/`，一次性审阅记录统一
  放入 `archive/reviews/`。
- 文件名中失效的“阶段三/四/五”前缀已从当前设计移除，入口 README 和历史引用已同步。
- 测试文件按当前职责调整为 `test_stage345_localization_geometry.py`、
  `test_stage6_slice_planning.py` 和 `test_stage7_reconstruction.py`。
- `spine_geometry.stage` 已从旧的 `stage3_localization` 改为
  `stage5_anatomical_analysis`；其余本轮注释整理不改变四棱柱、L5 端部恢复、椎间代表
  端边、CPR 或 MPR 医学几何算法。
- 根说明中的腰椎区间切已改为当前真实规则：从相邻四棱柱选择相向端边，在共同切向
  覆盖内取代表点，避免角点最近距离形成锐角。
- 第一至第八阶段均有一致的中文编号日志头和完成行；Pipeline 另行记录阶段序号、稳定
  英文名称、中文职责、开始/完成状态与耗时；失败时补充异常类型、原因、调用堆栈及
  被跳过的后续阶段。
- Pipeline 生命周期使用 `RunLog`；`ErrorLog` 在 RunLog 开启时同步落入运行日志，因此
  只开启 RunLog 的配置也能保留阶段失败上下文。
- `manifest.json`、`Response.stages/timings` 和调试报告使用八个稳定阶段名；运行时代码、
  入口及脚本中不再存在 `MappingStage`、`stage_mapping` 或 `mapping` 结果键。
- 测试套件已统一隔离控制台和文件日志入口；测试专用 `one/two` 阶段、`boom` 异常及
  其他模拟日志不会再污染实际日志目录，同时不改变调试产物开关。
