# 三状位重建参数请求设计

部位取景策略：普通 MPR 可配置 `framing_policy`，默认仅髋骨冠状位启用 `selected_region`、每侧 `5 mm`。
任意正数占比 p 的共同视野为“整组原标签包络尺寸+两侧余量”除以 `p/100`，固定面内中心、整组共用倍率。
100优先完整显示所选部位；占比降低时从未预裁的原 CT 逐渐显示更大外围，不保证80已露出全部皮肤，超源处保留正常无数据背景。
本文完整人体保护、`skin_edge` 及髋部逐层合法中心说明均指未启用该策略的计划；0/null和肺部正式策略保持原行为。字段、覆盖边界及诊断见[整组取景设计](../modules/reconstruction/2026-10-08-整组居中与FillPercent取景设计.md)。

## 当前请求

`Request` 包含输入/输出路径、`SlicePart`、`StudyType`、`ScanThickness` 和
`plane_configs`，以及可选 `cache_dir`、请求级 `window_presets`。
缓存详见 [缓存设计](2026-10-08-预处理与分割缓存设计.md)，窗位覆盖详见
[请求级窗位与 DICOM 显示设计](../modules/viewer/2026-10-08-请求级窗位与固定灰度显示设计.md)。
内部 Python 属性及模型配置键统一使用对应的
`slice_part`、`study_type`、`scan_thickness`。
外部 `ScanThickness` 必填，使用非负有限毫米数值；系统不再接收
`default/3mm/6mm` 档位，也不保留 `ScanThicknessEnum`。
切片方式由每个状位配置的 `SliceType` 显式指定，不再根据部位和状位自动推导。

每个 `PlaneConfig` 包含：

- `Plane`：横状位、矢状位或冠状位；
- `SliceThickness`：层厚，可选，`0` 表示未配置，非零值必须是正有限数值；
- `SliceSpacing`：层间距，可选，`0` 表示未配置，非零值必须是正有限数值；
- `SliceImageCount`：数量，可选，`0` 表示未配置，非零值必须是正整数；
- `WindowPresets`：一个或多个可从本次覆盖表或默认 JSON 查到的窗位名称；
- `SliceType`：`MPR`、`CPR`、`椎间隙`，省略时默认 `MPR`；
- `FillPercent`：可选数字，合法范围 `[0, 100]`，按共同取景尺寸控制输出图像占比。
  同组采用统一倍率，不逐张拉满。
  肺/髋普通 MPR 的 80 等 `0<FillPercent<100` 保持原目标中心与公式：肺部由最大实际目标
  bbox 面积参考层确定整组平移，髋骨按当前厚层目标居中；共同视野取标签目标尺寸/比例与
  既定中心下人体保护尺寸的逐轴较大值。100 则独立采用人体与目标并集的紧致视野，
  不再与旧标签对称视野取较大值：肺部给所有层追加同一个包络中心校正，髋骨共同视野取
  各层并集尺寸最大值，仅把原中心超出合法区间的坐标移入区间，合法坐标不动。
  100 的目标部位可偏离绝对正中，肺部肩臂仍可决定整组宽度，不逐层拉满小截面。
  正数每源提取一次完整人体支持，按实际源几何、厚层采样和 `2 mm` 余量保护皮肤、肋骨、
  骶尾骨、肩臂及双腿；外部空气与可可靠分离薄床板不限制倍率。人体不参与标签尺寸或
  肺参考层选择。人体不可识别的源层局部回退完整源盒，不能可靠分离的设备保守保留。
  同组各层各窗共用倍率、Rows、Columns 和 PixelSpacing，保留矩阵奇偶性，不执行后续上下 ROI。
  100 可校正面内中心，不能宣称相对源图只作整数 ROI 或保持原目标网格相位；DICOM 逐张记录
  实际中心、原点和方向。原计划法向、层位、范围、厚度、间距、张数和定位图保持不变。
  0、省略或 null 保留既有整组中心及基础像素间距，椎间隙仍统一裁空前矩阵。
  肺/髋普通 MPR 在这些值下同样保源、不做上下 ROI，scale=1，必要时扩大共同矩阵并保持奇偶性。
  除上述肺部、髋骨普通 MPR 外，平面成片在 HU 采样后逐张裁去首尾完全无源支持行，
  以裁后整幅图居中，0/null/省略同样执行；Rows 和垂直中心可不同，有效像素、Columns、
  PixelSpacing 不变。CPR 和 Localizer 不裁，不新增请求开关。具体规则见
  [整组取景设计](../modules/reconstruction/2026-10-08-整组居中与FillPercent取景设计.md)。
  旧 `line_extent_mode` 字段已移除并会在请求阶段报错。

层厚、层间距和数量必须传入其中两项或全部传入。缺少的一项由第六阶段结合当前
部位的有效范围计算；请求层只校验传参组合和基础类型。未提供 `plane_configs` 时
默认只请求横状位、1 mm 层厚、1 mm 层间距和骨窗；矢状位、冠状位虽然已实现，
但必须显式请求。

三个采样参数中的任意一项传入数值 `0` 时按未配置处理，并在参与规划的属性中规范化
为空；同时保留原始请求值，供交付报告准确回显。`PlaneConfig.to_dict()` 只序列化参与
规划的非空参数，`report.json` 则返回原始值，包括 `0`。处理 `0` 后仍必须保留两个或
三个有效参数。负数、布尔值、非有限数值以及非整数的正数数量仍然非法。

同一请求允许重复状位，用于一次生成不同层厚、层间距或数量的多份结果。第六阶段
按请求顺序为所有配置分配全局唯一的 `配置01`、`配置02` 标识，并为重复状位生成
`横状位`、`横状位1`、`横状位2` 这样的 `output_plane`。第七阶段直接按唯一状位名称
隔离目录，避免同名 DICOM 相互覆盖。

Linux 调用方必须以 UTF-8 传递 JSON 参数。仓库的 VS Code 启动配置和批量测试脚本
显式设置 `PYTHONUTF8=1`，因此即使基础环境是 `C` locale，也能正确解析中文协议值；
其他直接调用 `main.py` 的脚本应使用 UTF-8 locale，或同样设置该环境变量。

## 外部格式

CLI 使用 `--plane_configs` 接收 JSON 数组，例如：

```json
[
  {
    "Plane": "冠状位",
    "SliceThickness": 2.0,
    "SliceSpacing": 5.0,
    "SliceImageCount": 20,
    "WindowPresets": ["骨窗"],
    "SliceType": "CPR",
    "FillPercent": 80
  }
]
```

`PlaneConfig.from_dict` 把状位、`SliceType` 转为枚举，校验数字 FillPercent；窗位保持字符串。
Request 校验通过 `get_window_preset` 优先检查本次覆盖表，再回退默认 JSON。
`to_dict` 和第八阶段报告继续输出稳定的中文协议值。

## 参数计算

有效范围来自当前部位在当前状位上的实际解剖范围，并包含定位配置中的固定范围扩展。
总范围按 `层厚 + (数量 - 1) × 层间距` 计算：

- 传层厚和层间距时，计算完整覆盖有效范围所需的最少数量；
- 传层厚和数量时，根据有效范围计算层间距；
- 传层间距和数量时，根据有效范围计算层厚；
- 三项全部传入且总范围较大时，允许超出有效范围，并把超出部分均分到首尾；
- 三项全部传入且总范围较小时，数量保持不变，层厚和层间距均调整为
  `有效范围 ÷ 数量`。

椎间隙计划对每个有效间隙独立执行这套计算。`SliceImageCount=20` 表示每个间隙
20 张，不是全部间隙合计 20 张；如果识别到 5 个有效间隙，最终物理数量为 100 张。
缺失间隙不会参与计算，也不会把数量重新分配给其他间隙。

每次任务都生成 `report.json`。顶层包含布尔值 `Success`、文本 `Message`、`SlicePart`、
`StudyType`、数值类型的 `ScanThickness` 和 `PlaneList`。成功时 `Success=true` 且
`Message` 通常为空；部分脊柱椎间区间因标签或几何不足被跳过时，`Message` 去重汇总
被跳过的区间及原因，`PlaneList` 只返回实际生成的区域。失败时 `Success=false`、
`Message` 写入错误信息且 `PlaneList` 为空。
每个成功报告的 `PlaneList` 项通过全局唯一 `ConfigId`
对应一项原始请求，`SliceThickness`、`SliceSpacing`、`SliceImageCount` 原样返回请求值，
其中 `0` 仍保留。重复状位的 `Plane` 仍为 `横状位` 等医学名称；内部 `output_plane`
才按出现顺序命名为 `横状位`、`横状位1`、`横状位2`，用于隔离目录。
调用方通过 `ConfigId` 和区域 `Path` 识别对应结果，不把医学状位拼接为路径。
报告、Response 和计数口径详见 [交付报告与响应契约](2026-10-08-交付报告与响应契约设计.md)。

实际采样结果按磁盘目录顺序返回：每个 `WindowPresetList` 项包含窗位 `Name` 和
`RegionList`。每个重建区域只使用一个 `Region`，并返回 `ActualSliceThickness`、
`ActualSliceSpacing`、`ActualSliceImageCount` 和 `Path`。普通 MPR/CPR 使用
`default`；椎间隙使用 `C2_C3`、`L1_L2` 等下划线标识。

```json
{
  "Success": true,
  "Message": "",
  "SlicePart": "腰椎",
  "StudyType": "CT",
  "ScanThickness": 1.0,
  "PlaneList": [
    {
      "ConfigId": "配置01",
      "Plane": "横状位",
      "SliceType": "椎间隙",
      "FillPercent": 80,
      "SliceThickness": 5.0,
      "SliceSpacing": 5.0,
      "SliceImageCount": 20,
      "WindowPresetList": [
        {
          "Name": "骨窗",
          "RegionList": [
            {
              "Region": "L1_L2",
              "ActualSliceThickness": 5.0,
              "ActualSliceSpacing": 5.0,
              "ActualSliceImageCount": 20,
              "Path": "/output/横状位/骨窗/L1_L2"
            }
          ]
        }
      ]
    }
  ]
}
```

命令行统一使用 `--slice_part`、`--study_type`、必填 `--scan_thickness` 和
`--plane_configs`。HTTP/API 调用构造请求字典时使用 `SlicePart`、`StudyType`、
`ScanThickness`；旧 `body_part/check_type`、`slice_part/study_type` 外部字段以及
状位内的小写字段不再兼容。

## 模型区间

第二阶段从 `slice_part_config.json` 按检查类型和切割部位选择 `model_rules`，再使用
`scan_thickness_range_mm.min <= ScanThickness <= scan_thickness_range_mm.max`
匹配 `model_id`。上下限均为包含边界的毫米数值。未命中、配置边界非法或多个区间
同时命中都会明确报错，禁止静默回退。当前配置区间为 `0-1.5mm`、`1.6-4.5mm`、`4.6-6mm`；
肺部因为只存在原薄层模型，目前仅支持 `0-1.5mm`。

## 职责边界

请求层只校验结构和参数，不决定目标标签、实际采样参数或 MPR/CPR 几何。
预检确认检查类型/切割部位/状位/`SliceType` 组合可执行；第三阶段解析目标配置并选定图像空间，
第四、第五阶段形成定位与解剖几何；第六阶段根据有效范围计算实际层厚、层间距和
数量并产生 `SlicePlan`；第七阶段在保持切面和层位置的前提下按整组目标取景、采样和写出 DICOM。
取景公式和 CPR 边界见 [整组取景设计](../modules/reconstruction/2026-10-08-整组居中与FillPercent取景设计.md)。
