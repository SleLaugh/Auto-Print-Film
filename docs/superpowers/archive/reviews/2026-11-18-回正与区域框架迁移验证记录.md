## 3. 真实缓存病例对比

按八个部位各选五组任务，共 40 组，涉及 31 个原始 CT 序列。复用同一 CT 与分割缓存，
用改造前独立源码、旧配置和新版分别重跑第三至八阶段；请求参数来自原报告，窗参数
取自原 DICOM。没有重新执行神经网络分割，也没有复用第三至八阶段的整组输出。

| 项目 | 结果 |
| --- | --- |
| 双方成功 | 37 组 |
| 双方相同失败 | 3 组全脊柱，原分割缺少要求的颈椎标签 |
| 成功组中比较的 DICOM | 3134 张：2999 张切片、135 张定位图 |
| 改造前同输入复跑与新版 | 37 组的解码像素、受检几何/编码字段、相对输出路径及归一化报告均一致 |
| 原历史成片与新版 | 6 组一致，31 组存在差异；旧源码同输入复跑也出现相同差异 |
| 源文件检查 | 检查的 93 个源文件大小、修改时间未变 |

三个失败任务中，两组缺 C2–C4，一组缺 C2–C5；两版都在第三阶段失败。
该缓存中实际只有两组能满足本次全脊柱标签要求，因此不能写成“全脊柱五组成功”。

一致性比较忽略生成 UID、时间戳及患者描述字段，不等于 DICOM 文件逐字节相同。
原历史成片的代码版本与运行环境未被冻结，其差异不能归因于本次框架迁移，具体原因
未确定。每个部位选代表图做了可视检查，共 24 张“历史图／新版／差异”对照图；
可视抽查不替代全量像素与几何核验。

## 4. 性能复测

前次 37 组并行运行的总耗时约增加 1.41%，但受并发负载和运行顺序影响，不用它估计
框架自身开销。随后从每个部位成功任务中取一组接近中位耗时的病例，共八组；
每组旧版、新版各两次，合计 32 次，单任务串行运行，按部位交替 ABBA/BAAB 顺序。
全部运行成功，输出 DICOM 数量与对应对比任务一致。

两版使用同一解释器、依赖、CT/分割缓存、请求与窗参数；ITK 线程数为 4，OMP/BLAS
线程数为 1。计时覆盖 `Pipeline.run` 的缓存命中执行及第三至八阶段；不包含进程启动、
模块导入、配置/请求加载、Pipeline 初始化与前置缓存检查。另记录了完整进程墙钟耗时。

| 部位 | 旧版平均秒数 | 新版平均秒数 | 变化 |
| --- | ---: | ---: | ---: |
| 颅脑 | 8.241 | 8.233 | -0.09% |
| 颈椎 | 14.779 | 14.657 | -0.83% |
| 胸椎 | 14.456 | 14.579 | +0.85% |
| 腰椎 | 16.684 | 16.698 | +0.08% |
| 胸腰椎 | 52.169 | 52.635 | +0.89% |
| 全脊柱 | 81.841 | 81.823 | -0.02% |
| 肺部 | 4.996 | 5.025 | +0.59% |
| 髋骨 | 8.696 | 8.655 | -0.47% |

旧版 16 次累计 403.722 秒，新版 16 次累计 404.610 秒，增加 **0.22%**。
平均单任务从 25.233 秒变为 25.288 秒，增加 **0.056 秒**。各部位变化均在 ±1% 内。

完整进程平均墙钟耗时增加约 0.26%，CPU 时间增加约 0.20%；平均进程峰值 RSS 为
1177.976 MiB → 1176.540 MiB（约 -0.12%）。RSS 是整个进程的峰值，不是框架新增内存量。

在这些样本的缓存命中路径上，没有观察到明显性能退化。每版每病例仅两次，不足以
证明零开销或统计显著性；结果不包含模型推理，也不能直接外推到未来腹部、四肢或更大组合区域。
