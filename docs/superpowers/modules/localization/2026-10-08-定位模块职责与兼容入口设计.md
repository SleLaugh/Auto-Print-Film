# 定位模块职责与兼容入口设计

2026-10-08 补录 `397e03f`、`3c2f5ea`、`6e84ca1` 的职责拆分。
这些调整分离实现文件，不引入新的医学算法或新的流水线阶段。

## 职责划分

| 文件 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| `src/stages/localization_contracts.py` | 定位范围解析、标签别名、CPR 配置、结果字典及 JSON 序列化 | 主体筛选、四棱柱拟合和阶段状态 |
| `src/stages/localization_geometry.py` | bbox、二维凸包、四边形外包络、点在多边形内等基础几何 | 请求解析、文件写出和患者特例 |
| `src/stages/localization_execution.py` | 第四阶段上下文读取、快照复用/重建、纯标签定位结果交接 | 第三阶段的校正决策、第五阶段的解剖分析 |
| `src/stages/stage_localization.py` | `LocalizationOperations` 组合契约与基础几何、保留主体/棱柱算法及阶段类入口 | 第六阶段切片规划、第七阶段图像采样 |
| `src/planning/spine_cpr_math.py` | `Point3D` 的均值中心、点积、缩放、加法、叉积 | CPR 标签选择、曲线平滑与端点策略 |

`LocalizationOperations` 继承契约和几何 mixin；`LocalizationStage` 继承执行 mixin
及操作类，原有方法名和 `src.stages.stage_localization` 导入入口继续可用。
CPR 规划器以原有私有别名导入数学函数，不因抽取文件改变计算次序或单位。

## 第四阶段输入输出

必须存在 `spatial_correction` 结果。工作分割路径取该结果的
`seg_for_reconstruction_path`，不是自行再次决定是否回正。
`localization_workspace_v1` 不存在或其 `seg_path` 与工作路径不同时，重新读取分割并构建
label 索引、坐标、目标 mask 和 bbox；只有相同图像空间的快照可复用。

输出 `LocalizationStageResult`，包括全量 `coords`、图像几何、标签目标、已解析范围、
切法规则、CPR 配置、工作 raw/seg 路径和校正诊断。第四阶段不生成脊柱主体质心或端面，
这些由第五阶段补充。输出路径字段非空不等于当前阶段已经完成 JSON 写盘；
最终序列化由调用方按调试开关控制。

运行时快照包含数组和 SimpleITK 对象，不序列化为跨任务缓存，第五阶段结束后释放。
详见 [Label 快照复用](2026-08-05-Label快照复用设计.md)。持久文件缓存是另一条机制，
见[预处理与分割缓存](../../architecture/2026-10-08-预处理与分割缓存设计.md)。

## 不变条件与验证

- 维持原有 `xyz` 物理坐标、`zyx` 数组索引和 mm 单位边界，不因文件拆分转置坐标。
- 缺少前置结果或必要标签时明确失败，不用空对象伪造正常定位。
- 独立调用第四阶段可从前置工作路径重建快照；完整流水线避免重复全图扫描。
- 既有导入入口、结果字段和第三至七阶段数据流保持兼容。

直接测试入口为 `tests/test_localization_geometry.py`、`tests/test_spine_cpr_math.py`、
`tests/test_stage345_localization_geometry.py`；算法细节仍以主体、四棱柱、CPR 各设计为准。
