# 三状位重建参数请求设计

## 当前请求

`Request` 包含输入/输出路径、`StudyPart`、`StudyType`、`ScanThickness` 和
`plane_configs`。内部 Python 属性及模型配置键统一使用对应的
`study_part`、`study_type`、`scan_thickness`。
外部 `ScanThickness` 必填，使用非负有限毫米数值；系统不再接收
`default/3mm/6mm` 档位，也不保留 `ScanThicknessEnum`。
切片方式由每个状位配置的 `SliceType` 显式指定，不再根据部位和状位自动推导。

每个 `PlaneConfig` 包含：

- `Plane`：横状位、矢状位或冠状位；
- `SliceThickness`：层厚，必须大于 0；
- `SliceSpacing`：层间距，必须大于 0；
- `WindowPresets`：一个或多个 JSON 配置中存在的窗位名称；
- `SliceType`：`MPR`、`CPR`、`椎间隙`，省略时默认 `MPR`；
- `line_extent_mode`：定位线范围模式，只接受 `整平面`、`部位范围` 两个中文协议值，
  默认 `整平面`；请求、报告和调试输出不再使用旧英文值。

同一请求中状位不能重复。未提供 `plane_configs` 时默认只请求横状位、1 mm
层厚、1 mm 层间距和骨窗；矢状位、冠状位虽然已实现，但必须显式请求。

Linux 调用方必须以 UTF-8 传递 JSON 参数。仓库的 VS Code 启动配置和批量测试脚本
显式设置 `PYTHONUTF8=1`，因此即使基础环境是 `C` locale，也能正确解析中文协议值；
其他直接调用 `main.py` 的脚本应使用 UTF-8 locale，或同样设置该环境变量。

## 外部格式

CLI 使用 `--plane_configs` 接收 JSON 数组，例如：

```json
[
  {
    "Plane": "冠状位",
    "SliceThickness": 2.0,
    "SliceSpacing": 5.0,
    "WindowPresets": ["骨窗"],
    "SliceType": "CPR",
    "line_extent_mode": "整平面"
  }
]
```

`PlaneConfig.from_dict` 把状位、`SliceType` 和定位线模式转换为枚举；窗位保持字符串，并通过
`get_window_preset` 检查当前 JSON 配置。`to_dict` 和第八阶段报告继续输出稳定的
中文字符串。

命令行统一使用 `--study_part`、`--study_type`、必填 `--scan_thickness` 和
`--plane_configs`。HTTP/API 调用构造请求字典时使用 `StudyPart`、`StudyType`、
`ScanThickness`；旧 `body_part/check_type`、`study_part/study_type` 外部字段以及
状位内的小写字段不再兼容。

## 模型区间

第二阶段先按检查类型和部位选择 `_model_rules`，再使用
`min_scan_thickness <= ScanThickness <= max_scan_thickness` 匹配 `model_mapper`。
上下限均为包含边界的毫米数值。未命中、配置边界非法或多个区间同时命中都会明确
报错，禁止静默回退。当前配置区间为 `0-1.5mm`、`1.6-4.5mm`、`4.6-6mm`；
肺部因为只存在原薄层模型，目前仅支持 `0-1.5mm`。

## 职责边界

请求层只校验结构和参数，不决定目标标签、切片数量或 MPR/CPR 几何。
预检确认检查类型/部位/状位/`SliceType` 组合可执行；第三阶段解析目标配置并选定图像空间，
第四、第五阶段形成定位与解剖几何；第六阶段产生 `SlicePlan`；第七阶段执行采样
和 DICOM 写出。
