# AutoPrintFilm 框架基础实施计划

> 历史计划（2026-10-08 核对）：以下正文保留当时过程，阶段编号和规则不作为现状。
> 当前入口：[2026-07-10-框架基础设计](../../architecture/2026-07-10-框架基础设计.md)。
> 完整对应关系见[历史文档替代索引](../2026-10-08-历史文档替代索引.md)。

> **供执行人员使用：** 按任务逐项实施本计划，各步骤使用复选框（`- [ ]`）跟踪状态。

**目标：** 在不改变六阶段医学算法的前提下，增加统一配置、预检、任务状态、安全产物管理、标准错误和任务 manifest。

**架构：** 保留 `Request -> Pipeline -> Stage[] -> Response` 主链，在 Pipeline 外围注入不可变 `AppConfig`、`PreflightValidator` 和 `ArtifactManager`。Pipeline 独占生命周期变更，Context 保存有类型阶段结果和阶段记录，manifest 作为可恢复的运行事实记录。

**技术栈：** Python 3.10+、标准库 dataclasses/enum/json/pathlib/uuid、unittest、现有 SimpleITK/nnUNet 依赖。

## 全局约束

- 不改变预处理、分割、定位、规划、重建和报告的医学计算规则。
- 保留 `Pipeline()`、现有 `Request` 字段、Context 旧字典接口和业务输出路径兼容性。
- 不增加运行时第三方依赖，不引入数据库、队列、API、并发、重试或断点续跑。
- 预检失败不得创建或修改输出目录。
- 所有只读预检通过后，递归删除并重建本次任务专用 `output_dir`；预检失败不得删除。
- 不记录患者敏感 DICOM 字段或完整环境变量。
- 不执行 `git commit`；完成后仅提供建议提交信息。
