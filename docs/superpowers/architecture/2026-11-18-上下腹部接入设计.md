# 腹部接入设计（上腹部、下腹部、全腹部）

修订日期：2026-11-19。本文记录基于[回正与区域配置分离框架](2026-11-18-回正与区域配置分离设计.md)
接入模型 701 的上腹部、下腹部、全腹部规则。字段完整约束见[配置手册](../../../src/config/README.md)，
生产升级见[部署手册](../../production.md)。原有八个启用部位及禁用骶骨的配置保持不变。

## 1. 请求与模型

协议值为 `SlicePart=上腹部`、`SlicePart=下腹部`、`SlicePart=全腹部`。三者仅注册 CT 的横状位、冠状位、
矢状位 MPR；CPR、椎间隙和 MR 由能力预检拒绝。每个状位需要在 `plane_configs` 中
显式请求，未传该数组时仍沿用系统默认的横状位骨窗 MPR；腹部任务应明确选择腹部窗。

三个部位均按一个连续闭区间 `0 <= ScanThickness <= 6` 匹配模型 `701`，
规则显式指定 `configuration=3d_fullres`、`fold=0`、`input_orientation=RAS`。
`1.55 mm`、`4.55 mm` 也在该区间内，
不沿用原脊柱模型分段之间的空隙。`0–6 mm` 仅代表路由准入，不是模型在全部层厚上的
分割质量承诺；实际扫描覆盖与模型输出仍须逐病例检查。

运行时读取模型自己的 `dataset.json`，按语义名称解析以下标签，不在切割算法中硬编码编号：

| 标签 | 701 中的编号 | 本次用途 |
| --- | --- | --- |
| `liver` | 1 | 上腹部、全腹部上界与目标证据 |
| `hip_left` / `hip_right` | 2 / 3 | 三部位回正、目标证据及上腹部下界 |
| `kidney_left` / `kidney_right` | 4 / 5 | 下腹部上界与目标证据 |
| `femur_left` / `femur_right` | 6 / 7 | 下腹部、全腹部下界与目标证据 |

股骨标签包含股骨头，但没有单独的股骨头编号。当前按用户认可的定义，以分割股骨的
上端近似股骨头上界，不额外分割股骨头，也不据此保证每个异常姿态或不完整分割均准确。
`background` 和 `ignore` 不参与区域或回正。

### 推理输入的存储方向

本机模型 701 的训练图像采用 RAS 数组存储约定，训练未使用镜像增强，模型选择的
`NibabelIO` 不会自动把传入数组归一到该方向。正式 DICOM 转换得到的 CT 可为 LPS 存储，
两者不能仅因物理坐标记录正确就视作神经网络输入相同。此次实际推理检查发现过双侧标签
方向异常和碎片，因此模型规则显式声明 `input_orientation=RAS`。

第二阶段仅对临时推理输入做轴置换/翻转，不使用插值，也不改变原 CT 缓存的 HU、位置或
方向；预测标签恢复到原 CT 物理网格后再供后续阶段使用。分割缓存记录输入方向约定，
缺少该标记或方向不匹配的历史 701 结果不复用，需重新推理。原九部位未配置此字段，
保留其原推理输入行为，不修改模型权重、训练计划或全局其他模型。

这一步处理模型训练时的数组存储约定，与 `localization.pose` 的解剖回正职责不同：
它不把斜扫描重采样为正交体，也不代替双髋方向估计。符合模型输入约定仍不等于已验证
全部病例的分割质量。

## 2. 回正与头脚边界

三个部位的 `pose` 都复用已有 `hip` 方法，`roles.left/right` 分别引用双髋。
第三阶段保持原工作图像，第五阶段估计方向，第七阶段按该方向直接采样；肝、肾、股骨
不会因参与区域边界而自动加入回正。这里得到的是既有算法估计的髋部参考方向，
不是对通用临床标准解剖定位的承诺，质量不足时沿用其回退和警告规则。

下表的 `upper` 表示标签沿最终解剖头脚轴的最高投影位置，不是原数组 Z 的最大索引：

| 部位 | 区域上界 | 区域下界 |
| --- | --- | --- |
| 上腹部 | `liver.upper` | `max(hip_left.upper, hip_right.upper)` |
| 下腹部 | `max(kidney_left.upper, kidney_right.upper) + 30 mm` | `max(femur_left.upper, femur_right.upper)` |
| 全腹部 | `liver.upper` | `max(femur_left.upper, femur_right.upper)` |

全腹部按肝脏上界至股骨头上界定义，沿用上腹部的肝上界和下腹部的股骨上界。
双侧下端参考均取 `max`，即停在较高的一侧上界，不取平均也不取较低侧。
下腹部向头侧增加的 `30 mm` 写在 `bounds.upper.offset_mm`，不会再作为六方向余量重复添加。
该固定偏移是覆盖范围规则，尚不能据此宣称实际肾上腺已完整覆盖；扫描范围和分割偏差
都可能影响最终覆盖。必需标签缺失、空标签、上下界反转或无有效区域时明确失败。

上腹部 `target_labels` 为肝、双髋，不要求双肾存在；下腹部为双肾、双髋、双股骨。
全腹部为肝、双髋、双股骨，共五个标签，不依赖双肾，也不使用下腹部的肾上方 `30 mm` 偏移。
这些标签提供目标证据与体表主体锚点，不以器官包围盒代替完整腹部的左右、前后范围。

## 3. 左右、前后范围

普通 `whole_range` 新增可选字段 `transverse_source`：

| 值 | 行为 |
| --- | --- |
| `labels`，省略时默认 | 保持原目标标签的左右、前后覆盖，不执行 CT 体表提取。 |
| `body` | 保持已求解的回正方向和上下界，在该头脚范围内用原 CT 体表确定左右、前后覆盖。 |

三个腹部区域设为 `body`。第五阶段先通过通用标签边界求解器得到头脚范围，再补体表的
LR/AP 范围；不会让体表反过来改变双髋方向、肝肾股骨端点或头脚偏移。
同次求解复用体表提取和方向投影，不因三个 MPR 状位重复提取整卷体表。

排臂采用保守策略：目标标签锚定中央躯干，仅排除与其可靠分离的外围组件；与躯干相连的
手臂、无法可靠区分的组织继续保留，不用激进切割收窄腹部。
腹部沿用身体主体的面积、跨度和厚度门槛，不重新加入已被该规则拒绝的独立小组件，
避免带较厚边缘的弧形床板再次扩大画框。符合主体条件的多个身体组件仍保留；这一选择
仅用于新 `body` 区域，不改变旧部位的取景行为。
体表不可识别的源层以该层原 CT 视野与所选头脚范围的交集补足 LR/AP，并记录警告，
不会退回肝肾包围盒冒充身体覆盖；整段与原 CT 没有有效交集时失败。
这项回退可能增大视野或保留扫描床、外围组织，不会补出扫描外的真实身体。

已求解区域保留 `transverse_source=body`、`constrained=true` 和 `transverse_support`
诊断，包括体表来源、排臂策略、各方向是否回退及回退源层数量。诊断随区域进入后续计划，
重建阶段消费已求解范围，不重新用完整双髋或某层的局部器官范围替代它。

## 4. 配置与取景

以下是下腹部的定位配置片段；上腹部使用上一节列出的标签及边界，完整配置以
[`slice_part_config.json`](../../../src/config/slice_part_config.json) 为准：

```json
{
  "pose": {
    "method": "hip",
    "roles": {"left": "hip_left", "right": "hip_right"}
  },
  "regions": {
    "default": {
      "type": "whole_range",
      "transverse_source": "body",
      "target_labels": ["kidney_left", "kidney_right", "hip_left", "hip_right", "femur_left", "femur_right"],
      "bounds": {
        "upper": {"labels": ["kidney_left", "kidney_right"], "edge": "upper", "reduce": "max", "offset_mm": 30.0},
        "lower": {"labels": ["femur_left", "femur_right"], "edge": "upper", "reduce": "max", "offset_mm": 0.0}
      }
    }
  }
}
```

全腹部复用相同的 `pose`，将 `regions.default` 配置为以下内容；上下边界均无需额外偏移：

```json
{
  "type": "whole_range",
  "transverse_source": "body",
  "target_labels": ["liver", "hip_left", "hip_right", "femur_left", "femur_right"],
  "bounds": {
    "upper": {"labels": ["liver"], "edge": "upper", "reduce": "max", "offset_mm": 0.0},
    "lower": {"labels": ["femur_left", "femur_right"], "edge": "upper", "reduce": "max", "offset_mm": 0.0}
  }
}
```

三个状位都引用 `default`，六方向 `face_extension_mm` 初始全部为 `0`。
如后续调整外扩，仍在解析完区域后增加；不得把下腹部的 `30 mm` 同时重复填进 `top_mm`。
横状位、冠状位使用矢状定位图，矢状位使用冠状定位图。

三个状位统一使用：

```json
{
  "basis": "selected_region",
  "margin_mm": 0.0,
  "centering": "group",
  "canvas": "target"
}
```

正数 `FillPercent` 以解析后的区域为取景目标，使用整组中心与目标画布；层内肝肾或髋骨
截面变小不会单独放大该层。`0`、`null` 或省略时保持基础像素间距和已解析区域。
区域是采样和取景范围，不是把 CT 除器官标签外的组织抹掉；源 CT 继续提供全部真实像素。
上下裁空沿用普通 MPR 的既有规则，最终 DICOM 的行数、中心应以各张写出的几何为准。
定位图不随 `FillPercent` 改变底图几何；定位线来自实际计划切面。

## 5. 部署与服务端接入

当前部署副本使用以下目录，所选全局 `_plans` 默认为 `nnUNetPlans`：

```text
nnUNet_results/Dataset701_AbdomenPelvis7/
  nnUNetTrainer__nnUNetPlans__3d_fullres/
    dataset.json
    plans.json
    fold_0/checkpoint_final.pth
```

目录中的 `nnUNetPlans` 是本次推理 `-p` 使用的查找名称；当前 `plans.json` 内的
`plans_name` 为 `nnUNetPlans24GB`，属于训练产物元数据，不应仅根据这个内部值把路由改成
`-p nnUNetPlans24GB` 或改动模型文件。实际路径需与参数匹配；部署别的目录命名时应相应
配置规则 `plans`，并核实完整训练产物。无需改变其他部位的全局模型设置。
701 当前未列入 GPU 重采样映射，沿用默认 CPU 重采样；这不代表神经网络改用 CPU 推理。

更新应用需要重新构建发布包并同步新 JSON；只替换 JSON 而继续运行旧程序无法识别新部位
和 `transverse_source`、`input_orientation`。同一序列三个腹部部位可以共用方向标记匹配的模型 701
分割缓存，输出目录仍须分别指定。
输入缺少目标结构不能通过复用缓存绕过定位校验。

服务端默认 `SliceRuleConfigInfos` 已追加上腹部、下腹部、全腹部各三条 CT/MPR/Default 规则。
`Initialize()` 仅在规则集合为空时填默认值，不自动修改已保存的配置。已有服务部署须在
原完整配置上手工合并缺少的组合；已接入上下腹部的实例还需追加全腹部三条规则，
并按业务配置对应切片方案、窗位与输出参数，保留已有部位规则。未配置任务方案时，Python 支持新部位并不代表服务会自动派发腹部任务。

服务还先通过预设配置 `BodyPartMappings` 将 DICOM 的 `BodyPartExamined` 映射为医院
使用的 `StudyPartName`，再按该名称、CT 类型及层厚匹配切片方案。当前默认映射不含
`ABDOMEN`；医院应按本机实际 DICOM 值添加映射，并使腹部方案的 `StudyPartName` 与其
一致，再把方案的 `SlicePartName` 设为 `上腹部`、`下腹部` 或 `全腹部`。名称映射不是 Python 部位
枚举，不能只增加 MPR 规则就省略该步骤。缺少映射或匹配方案时，服务会记录“不切割”。

## 6. 验证边界

配置测试覆盖协议解析、三状位能力、701 连续厚度匹配、回正与边界定义、体表字段校验及
CPR/椎间隙/MR 拒绝。几何与重建验证需要同时检查上下界、躯干横向覆盖、回退诊断、
正数与零占比，以及不完整标签和斜扫描情形。
既有八部位的框架迁移图像/性能记录不能直接充当新增腹部的病例效果证据。
实际 DICOM 验证及覆盖结果应单独记录，不把固定 30 mm 或股骨上端规则视为临床覆盖保证。

[上下腹部验证记录](../archive/reviews/2026-11-18-上下腹部实现验证记录.md)。该记录不包含
全腹部，不能作为全腹部的实际病例验证证据。

2026-11-19 全腹部专项验证执行 `tests/test_abdomen_part_config.py`、
`tests/test_abdomen_pipeline.py`、`tests/test_config_loader.py` 和
`tests/test_stage6_slice_planning.py`，结果为 `205 passed, 597 subtests passed`，Ruff 检查通过。
合成 CT 验证覆盖三状位实际 DICOM 写出、`FillPercent=0/50/100`、缺双肾仍成功，
以及缺肝、单侧髋骨或单侧股骨时失败。
