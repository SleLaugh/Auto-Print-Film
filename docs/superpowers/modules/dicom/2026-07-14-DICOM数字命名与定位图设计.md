# DICOM 数字命名与定位图设计

## 正式切片

每个计划和窗位目录内的正式重建切片使用从 `1.dcm` 开始的纯数字文件名。
`InstanceNumber (0020,0013)` 同样从 1 开始连续递增，但文件名只是交付组织，
不能改变切片物理几何。

阶段六只把完整文件名匹配正整数的 DICOM 当作正式切片，按数值顺序校验数量、
`InstanceNumber`、Series UID 和空间信息。

## 定位图

每个窗位目录同时保存不编号的 `Localizer.dcm`。定位图使用原始 CT 正交参考层
作为背景，绘制当前计划的定位线，并使用独立 Series UID。它不计入正式切片数量。

- `plane_stack` 绘制真实切片平面与定位面的交线；
- `curved_stack` 投影 CPR 曲线，当前只绘制 `offset=0` 基准中心线。

debug 模式在相同目录额外写 `Localizer.png`，非 debug 模式不产生 PNG。

## 写盘约束

正式切片和定位图均须经过 GDCM 串行保护入口。写盘后恢复阶段四计划的
`ImagePositionPatient` 和 `ImageOrientationPatient`，避免二维定位图显示轴
覆盖真实患者物理方向。
