## 两层配置

CASES 每项为 `输入目录名|输出目录名|切割部位|扫描层厚(mm)`，
扫描厚度用于选模型，不等于输出层厚，也不是查看器打开后的缩放单位。

SLICE_TYPE_CONFIGS 每项为
`切割部位|状位|切割方式|输出层厚(mm)|输出层间距(mm)[|FillPercent]`。
第六项省略或 0 不缩放；仓库当前条目显式填 80。
脚本不读取 .vscode/launch.json，修改调试配置不会影响批量请求。

脚本按横、矢、冠顺序组织请求，每个状位保留所有匹配条目；
颈椎/腰椎的横状位 MPR 和椎间隙、脊柱的矢状位及冠状位 MPR 和 CPR
均不能按状位去重。
输出四套窗位：骨窗、肺窗、纵隔窗、软组织窗。
当前颈椎椎间隙是 3/3 mm，其余条目 5/5 mm；具体以脚本配置为准。

当前默认 CASES 覆盖颈椎、胸椎、腰椎、脊柱、肺部、髋骨，并未列入颅脑病例；
“程序支持颅脑”不等于批量脚本已经遍历它。新增部位时要同时添加三状位切法和 CASES。
脊柱使用 C7–S1 整体范围，批量请求包含三状位 MPR、矢状位 CPR 和冠状位 CPR。
缺少某状位匹配配置会记录失败，不默默回退 MPR。

## 调度和失败语义

- `--dry-run` 只检查配置/输入并打印命令，不启动 main.py，也不生成结果；输入缺失仍记录失败。
- `--jobs N` 控制最多并发病例数，默认 1，必须为正整数；它不是单病例窗位线程数。
- 主循环启动后台进程，并按队列顺序等待；不是实时监测所有进程谁先结束。
- `--stop-on-failure` 在检测到失败后停止新增任务，等待已经启动的任务，不强杀它们。
- 任何失败或输入缺失最终退出 1，全部完成退出 0。
- 批处理日志固定在各输出目录的 `log/BatchLog.txt`，与程序日志位于同级 log 目录。
- 显式设置 PYTHONUTF8=1，确保 C locale 环境中中文 JSON 参数可解析。

当前批量命令不传 cache_dir 或请求级 window_presets；有缓存的单次调试不表示批量也会命中。
并发数不会自动根据 GPU 显存调整，同一输出目录不可同时运行多个任务。

## C# Worker 调度与同序列复用

Worker 的 `MaxConcurrentCount` 是所有在途应用进程的全局上限，不是每医院、每序列的上限。
当前每批扫描一个检查（`handleCount = 1`），启动 Python 后立即继续派发，不等待其处理完成；
该批次大小不代表 Python 任务的并发上限。
启动时先恢复各医院的在途进程，派发时在同一临界区内检查全局名额和规范化输出路径，
启动后登记进程。同一输出目录继续互斥；同一原始序列的任务使用不同输出目录时允许并发。
监测某任务的完成状态只依据其 PID、输出目录和报告，不因同序列的其他输出仍在处理而等待。

Worker 为同序列任务提供相同的序列级 cache_dir。Python 第一阶段缺失缓存时跨进程
单写，第二阶段按缓存目录和模型 ID 单写，等待任务复查并复用；不同模型的推理可独立运行。
已完成缓存只读复用，第三至八阶段在每任务输出目录并行；保留缓存锁和工作目录租约。
这不会让当前批量脚本自动传入 cache_dir；脚本需要共享缓存时仍须显式改造调用参数。
单次推理的时限、进程清理及有限重试由 Python 负责，C# 不增加任务超时判断。

## 操作与验证

```bash
bash -n scripts/batch_test_plan.sh
bash scripts/batch_test_plan.sh --dry-run
bash scripts/batch_test_plan.sh --jobs 2 --stop-on-failure
```

最后一条会真正执行任务，应仅在明确授权切割和输出位置后使用。
`tests/test_batch_test_plan_script.py` 覆盖参数、同状位的 MPR/间隙及 MPR/CPR 配置、
脊柱病例和五种输出组合、FillPercent 的默认/省略/0 透传、日志布局及 UTF-8。

`tests/test_service_dispatch_concurrency.py` 提取实际 C# 调度方法编译运行，覆盖七种调度场景；
需要 .NET SDK 6 或更新版本。仓库没有完整服务 csproj，该 harness 不替代服务端仓库的完整构建。
`tests/test_same_series_pipeline_concurrency.py` 验证实际 Pipeline 多进程下的缓存复用及任务输出隔离。
