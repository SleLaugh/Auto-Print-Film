# DICOM 数字命名与定位图设计

## 正式切片

每个计划和窗位目录内的正式重建切片使用从 `1.dcm` 开始的纯数字文件名。
`InstanceNumber (0020,0013)` 同样从 1 开始连续递增，但文件名只是交付组织，
不能改变切片物理几何。

第八阶段只把完整文件名匹配正整数的 DICOM 当作正式切片，按数值顺序校验数量、
`InstanceNumber`、Series UID 和空间信息。

## 定位图

每个窗位目录同时保存不编号的 `Localizer.dcm`。定位图使用原始 CT 正交参考层
作为背景，绘制当前计划的定位线，并使用独立 Series UID。它不计入正式切片数量。

- `plane_stack` 绘制真实切片平面与定位面的交线；
- `curved_stack` 按实际 CPR 弧长采样投影全部有效 offset 中心线；若计划未包含
  `offset=0`，定位图额外补画基准中心线。

背景状位和固定原始层由第六阶段计划中的 `localizer_plane`、
`localizer_reference` 决定。多个计划可以共享同一背景层，但仍分别叠加自己的
定位线；这两个字段不改变正式切片几何。腰椎共享选层规则见
`../reconstruction/2026-08-11-腰椎统一中心定位图设计.md`。

debug 模式在相同目录额外写 `Localizer.png`，非 debug 模式不产生 PNG。

## 写盘约束

正式切片和定位图均须经过 GDCM 串行保护入口。写盘后恢复第六阶段计划的
`ImagePositionPatient` 和 `ImageOrientationPatient`，避免二维定位图显示轴
覆盖真实患者物理方向。

同一计划的多套窗宽窗位只改变 Localizer 像素灰度、Series UID 和描述，不改变
空间几何。第七阶段必须在进入窗位线程前冻结原始 Localizer 的位置和方向，等正式
切片窗位任务全部完成后，再在主线程按窗串行写出定位图。四个窗的
`ImagePositionPatient`、`ImageOrientationPatient`、Rows 和 Columns 必须一致。
两项空间标签任一缺失时应直接失败，不能接受 GDCM 生成的二维默认值。
