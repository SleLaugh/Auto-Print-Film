## 交付 report.json

顶层固定为 `Success`、`Message`、`SlicePart`、`StudyType`、`ScanThickness`、`PlaneList`。
第八阶段必须先校验磁盘 DICOM，成功后才发布非空结果；失败报告包含错误消息且 PlaneList 为空。
报告通过同目录临时文件替换写入，避免读到半份 JSON；输出目录不可写、强制杀进程等限制仍适用八阶段设计。

每个 PlaneList 项对应一项请求配置：

- `ConfigId`：按请求顺序分配的全局唯一配置标识，例如 配置01。
- `Plane`：医学状位，重复配置仍写 横状位/矢状位/冠状位，绝不添加目录序号。
- `SliceType`：实际切法；同一配置不能混合多个实际切法。
- `SliceThickness/SliceSpacing/SliceImageCount`：原始请求值，包括 0；未提供为 null。
- `FillPercent`：传入时回显，0 保留，省略或 null 不输出此键。
  数学上的整数统一输出 JSON 整数（100 或 100.0 输入均输出 100），兼容 .NET 整数属性；
  非整数如 80.5 保留原数值，不截断或四舍五入。只接受整数的调用方应只提交整数比例。
- `WindowPresetList`：按请求窗位名称去重，逐窗包含 Name 和 RegionList。

每个 RegionList 项包含 `Region`、`ActualSliceThickness`、`ActualSliceSpacing`、
`ActualSliceImageCount`、`Path`。普通 MPR/CPR 的 Region 为 default，
椎间隙为 C2_C3、L1_L2 等；真实目录以 Path 为准，不通过 Plane 猜测。
`ActualSliceThickness`、`ActualSliceSpacing` 在交付报告中取两位小数，保持 JSON 数值
类型，不改成字符串，也不要求补零显示。请求回显、内部采样计算、调试记录和 DICOM
参数保留原精度。

## nnUNet 推理失败消息（2026-10-16 更新）

第二阶段不再将非零退出时的整段 stderr 直接作为报告 Message。
识别到 nnUNet 的 `Could not find a dataset with the ID <编号>`，且编号与本次选模一致时，
报告写出中文“未找到模型 <编号>”、对应的 `Dataset<至少三位编号>*` 目录前缀、
实际传给子进程的三个 nnUNet 查找目录以及检查路径/部署模型的处理建议。
编号和路径均由本次执行动态取得，不按病例或固定模型号硬编码；未配置目录明确标注。

这是外部进程失败后的错误分类，不是新增的模型文件预检。数据集目录缺失、权重文件缺失、
GPU 内存不足是不同故障，不应一律报成“模型找不到”。不匹配已知类型时，报告保留模型 ID、
退出码及短摘要（最多 300 字符再加省略号），优先提取 stderr/stdout 中具体的异常原因，
避免只显示末尾通用的 `Background workers died`。后台进程失败优先保留更早的具体原因；
普通失败优先保留 stderr 的末条具体异常，再回退 stdout 的具体异常。没有异常行时优先使用
stderr 的末条非空说明，避免被正常 stdout 进度覆盖。只有后台进程死亡提示时，不直接断言
内存不足；后台进程自身的 Python 异常、系统内存不足杀进程等均需查看完整日志确认。
实际命令和完整 stderr/stdout 交给 ErrorLog，独立于调试日志开关；默认外置配置已开启
`error_log_file_enabled`，文件位于本次任务输出目录的 `log/ErrorLog.txt`，仍尊重显式关闭配置。

阶段抛出 `ExternalProcessError`，由现有 Pipeline 生成 `Success=false`、空 PlaneList 的
失败报告，不新增交付 JSON 字段，不自动换模型或重试。Response 和调试 manifest 沿用标准错误契约。
模型目录可能含本机路径，外发报告仍需审查。已生成的历史报告不会自动重写。

验证见 `tests/test_segmentation_failure_report.py`：不同模型号、目录配置覆盖与环境继承、
其他错误不误分类、后台进程具体异常摘要、完整命令及日志保留、流水线失败报告落盘以及成功输出归一化。

## 重复状位与计数

例如同一请求有横状位 MPR 与横状位椎间隙，两项报告的 Plane 都是横状位，
但 ConfigId 不同，输出目录分别为 横状位、横状位1。后者是内部 `output_plane`，
仅用于隔离文件，不是新的医学状位。

`slice_count` 是计划中实际切片数，`image_count` 是按窗位展开的正式 DICOM 数，
均不包含 Localizer。多个椎间隙各自有一套实际采样参数，不能把请求数量理解为所有间隙合计。
第七阶段 `planes` 按输出目录名汇总；Response 的三个便捷 count 从基础名称的
axial/sagittal/coronal 项读取，不应假设它们自动合并了所有带编号的重复配置。
需要完整统计时读取所有计划 outputs 或报告各配置，且避免跨窗重复累计切片。

## Response 与诊断

`Response.to_dict()` 提供小写 success、output_dir、total_time、errors、timings、
axial_count、sagittal_count、coronal_count、job_id、status、warnings、stages。
errors 为阶段和消息列表，warnings 为结构化警告，stages 为各阶段状态；
此结构不能当成大写字段的 report.json。

阶段详细结果通过 context/Response.get_stage_result 读取；debug 开启时，
`metadata/处理报告_调试.json` 保存详细结果与输出校验。取景的 framing
诊断在第七阶段结果中；mode=group、source=group_target表示共同目标取景来源。
当前肺/髋正数普通MPR的selected_region记录basis、margin_mm、centering、canvas及原标签整组未加余量边界；
默认centering=group、canvas=original，六条规则center_source均为group_selected_region，包含小标签和空层。
没有默认reference_slice_index/reference_shift_mm等参考层字段。framing_target_size_mm为组标签投影尺寸加余量，
slice_target_size_mm仅记录各厚层诊断。output_spacing_mm记录实际间距，output_size_xy保留原Stage6矩阵。
原CT投影画框物理宽高比由N*基础间距决定；实际FOV=N*output_spacing_mm，在该比例内等比容纳目标。
100的两个方向视野未必等于标签尺寸，70、50保持同一组中心与矩阵，宽高均扩为100的1/0.7、2倍。
正数不加载人体支持、不记录source_preservation或skin_edge字段；外围组织允许越框，完整原CT采样保留。
显式兼容reference/slice_target或target画布仍可产生自身诊断，不代表当前默认肺/髋行为。

其他部位保留slice_target、slice_symmetry_plane、group_fallback、group_target等原有来源，
context_label_ids记录获准显示上下文。当前脊柱/脑骨上下文不因肺髋调整改变。
肺/髋0/null/省略仍记录source_preservation.mode=complete_source_slab、required_size_mm、
field_of_view_mm和zoom_limited；基础间距、scale=1与整组中心保持，必要时扩共同矩阵，
zoom_limited不表示矩阵扩展。未配置策略的旧肺/髋计划或内部工具仍可产生人体/skin_edge兼容诊断，
这些不代表当前默认正数生产策略。最终center和DICOM位置必须一致，
原切面、法向范围、层厚、间距、张数及定位图不变，诊断不回写原计划source_labels。
不把逐层空间元数据塞入简洁交付协议。
交付报告的窗位只有名称，不完整记录每项请求级窗宽窗位覆盖值。

## 报告对比工具

在仓库根目录执行：

```bash
PYTHONPATH=. python scripts/compare_results.py /path/to/baseline /path/to/candidate
```

仅将落在各自结果根目录下的绝对 Path 转为相对路径，再递归比较 JSON。
一致退出 0，存在差异输出字段路径及左右值并退出 1；数组顺序参与比较。
移走目录后，报告内旧绝对路径不一定能归一化。
工具不比较 DICOM 像素、物理几何或真实窗位，报告相等不代表图像相等。
