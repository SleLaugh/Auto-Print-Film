# 阶段五 GDCM 写盘串行保护实施计划

> **供执行人员使用：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项实施本计划。各步骤使用复选框（`- [ ]`）跟踪状态。

**目标：** 保留窗位灰度计算并行，同时禁止 SimpleITK/GDCM DICOM 写入器在同一进程内并发执行。

**架构：** 在 `src/reconstruction/dicom.py` 增加唯一的 GDCM 写盘入口和进程内互斥锁，锁住写入器从创建到销毁的完整生命周期；CT 成片和定位图统一调用该入口。阶段五线程池、MPR 采样、pydicom 标签修复和目录结构保持不变。

**技术栈：** Python、threading、SimpleITK/GDCM、pydicom、unittest。

## 全局约束

- 不修改髋骨解剖坐标、阶段四计划或 MPR 几何。
- 不关闭窗位线程池；仅串行保护 GDCM 原生写盘。
- CT 成片和定位图必须共享同一把锁。
- 写盘异常、临时文件清理和原子替换行为保持不变。
- 所有新增方法和锁必须补充中文注释。
- 本轮不执行 Git 提交。

- 输出：`_execute_gdcm_write(image: sitk.Image, output_path: Path) -> None`，保证同一进程最多一个 GDCM 写入器存活。

在四个线程开始调用 `write_ct_dicom` 前使用 `threading.Barrier(4)` 对齐时序；替换
`sitk.ImageFileWriter` 为记录活动数量并短暂等待的测试写入器。断言四个输出存在且
`max_active_writers == 1`。

- [x] **步骤 2：运行测试并验证红灯状态**

运行：`.venv/bin/python -m unittest tests.test_stage5_reconstruction.Stage5ReconstructionTest.test_gdcm_writer_lifecycle_is_serialized_across_window_threads -v`

预期：测试失败，当前四个线程可同时进入测试写入器的 `Execute`，最大活动数大于 1。

- [x] **步骤 3：实现最小范围的串行写入器**

在 `src/reconstruction/dicom.py` 定义模块级 `threading.Lock`，并增加统一写入方法：

```python
def _execute_gdcm_write(image: sitk.Image, output_path: Path) -> None:
    with _GDCM_WRITE_LOCK:
        writer = sitk.ImageFileWriter()
        try:
            writer.SetFileName(str(output_path))
            writer.KeepOriginalImageUIDOn()
            writer.Execute(image)
        finally:
            del writer
```

`write_ct_dicom` 和 `write_localizer_dicom` 均改为调用该方法，不能在其他位置直接
创建 `ImageFileWriter`。

- [x] **步骤 4：运行针对性测试并验证绿灯状态**

运行：`.venv/bin/python -m unittest tests.test_stage5_reconstruction -v`

预期：新增并发契约测试和既有阶段五测试全部通过。
