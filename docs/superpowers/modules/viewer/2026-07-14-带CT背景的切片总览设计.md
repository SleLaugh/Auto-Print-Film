# 带 CT 底图的切片总览设计

## 目标

第六阶段用带 CT 底图的总览替换现有细化网格纯标签总览，为每个已生成状位输出
一张能够直接在 ITK-SNAP
中作为 Main Image 打开的演示 NIfTI。文件包含重采样后的原始 CT、真实层厚覆盖带
和切片中心线，不需要通过 Load as Segmentation 附加。

## 输入与网格

- CT 输入使用定位结果中的 `raw_for_reconstruction_path`，缺失或文件不存在时不
  生成带底图总览，其他第六阶段产物不受影响。
- 输出网格完全复用对应细化总览的 size、spacing、origin 和 direction，
  保留完整原图可见范围。
- CT 使用 SimpleITK 线性插值重采样；默认填充值使用原图最小强度。
- 本产物只用于 debug 演示，不替代 `raw_for_reconstruction_path`，也不参与第七阶段。

## 绘制

- 复用现有总览的计划分组、观察层、层厚范围和中心位置。
- 只在现有总览绘制所在的固定正交层上覆盖 CT，避免把整组三维切片平面烧入原图。
- 层厚覆盖带写为高亮强度；中心线在覆盖带内写为更高强度，使两者能够区分。
- 高亮值从当前 CT 强度范围向上扩展，并限制在 `int16` 范围内。
- 输出使用 `int16`，在保留完整三维 CT 的前提下，将单体素存储从
  `float32` 的 4 字节降为 2 字节。

## 输出

按实际请求状位生成：

```text
切片总览含原图_横_整.nii.gz
切片总览含原图_矢_整.nii.gz
切片总览含原图_冠_整.nii.gz
```

区间切沿用既有 `_区` 后缀。第六阶段结果和 `slice_plans.json` 新增按状位路径字典
`debug_slice_plan_overview_with_image_paths`。原始网格总览及其字段保持不变。

不再生成细化网格的纯标签 `切片总览_横/矢/冠_*`。单路径摘要字段
`debug_slice_plan_overview_overlay_path` 指向横状位或请求中第一个可用的
`切片总览含原图_*`；现有 `debug_slice_plan_overview_paths` 同样保存新的含原图
路径，避免下游出现空路径。`切片原始网格总览_*` 继续保留，用于附加原始 CT
进行技术核对。

## 测试

- 验证 CT 被线性重采样到总览参考网格要求的图像信息。
- 验证非绘制区域保留重采样 CT 强度。
- 验证层厚带高于 CT 最大值、中心线高于层厚带。
- 验证只生成请求中实际存在的状位。
- 验证缺少原始 CT 时安静跳过带底图总览。
- 验证输出保留完整总览网格尺寸，且像素类型为 `int16`。
- 运行完整测试，确认第七阶段输入和原有调试产物不变。
