# 架构文档入口

优先读本文件。只有任务涉及跨阶段契约、请求结构、框架生命周期或 DICOM 写盘并发时，才继续读取本目录具体设计。

## 当前有效规则

- 八阶段主链是 `Request -> Pipeline -> Stage[] -> Response`：前处理、分割、空间校正、
  标签定位、解剖分析、切片规划、图像重建、校验与报告。
- 原第三阶段已拆为 `SpatialCorrectionStage` / `LocalizationStage` /
  `AnatomicalAnalysisStage`；三者共享进程内 label 快照，但分别登记阶段结果。
- 头骨、髋骨、肺部将姿态估计延后到第五阶段，并在第七阶段按最终方向采样，不在
  第三阶段重复整卷 XY 旋转。脊柱第三阶段只提升可靠逐椎体镜像角汇聚得到的 XY 候选。
- 当前启用部位的整切三状位统一消费第五阶段解剖坐标；头骨/髋骨/可靠双侧肺使用
  左右对称面，颈胸腰结合首尾轴和可靠逐椎体左右方向。质量不足明确警告并回退，
  头骨保留输入前后倾斜基准。刚性采样几何与 DICOM 标签一致，不强制镜像或变形组织。
- `patient_reference_axes` 统一按患者语义校准存储轴符号，SI 朝 LPS `+Z`，冠状、矢状
  成片头侧向上；原 direction 仍负责物理点换算，已有斜角和头部俯仰基准不变。
- 镜像姿态必须通过 LR 方向唯一性检查；AP/SI 等谱而 LR 独立时不误拒。肺部还须
  在镜像质量通过后验证两个主体分居候选面两侧、沿 LR 分离且反射跨主体对应。
- S1 标准配置保持不变，运行时按实际 `label_targets` 优先解析 `vertebrae_S1`、
  再回退 `sacrum`；整体轴、诊断、椎间主体配对和计划均使用同一实际标签。
- label 快照的生命周期止于第五阶段；第五阶段无论成功或异常都必须释放完整分割、
  逐标签体素索引和目标 mask，第六至八阶段不得依赖该快照。
- 切片规划统一使用 `PlanningStage` 和 `planning` 结果键，不保留
  `MappingStage` 或 `mapping` 别名。
- 框架能力围绕配置、预检、任务状态、产物管理、标准错误和 manifest 收口。
- `debug_file_enabled` 唯一控制调试文件和中间现场，`debug_log_file_enabled` 只控制
  `DebugLog.txt`，两者保持独立。
- 三类程序日志和批处理单病例日志统一位于任务输出目录的 `log/`；任务重建输出目录时
  只保留该日志目录，其余旧业务结果仍全部清理；每个任务使用固定日志文件名，不再按
  日期和小时分层。
- 外部请求的状位配置属于系统契约，具体重建、切片和显示规则分别在模块目录维护。
- `cache_dir` 复用第一阶段原始 NIfTI 和第二阶段按模型隔离的分割；缓存不做输入内容指纹校验，
  必须由调用方按病例隔离，不能置于会清理的输出目录内。
- 请求级 `window_presets` 可覆盖默认窗位；`FillPercent` 在第七阶段确定整组共同倍率，
  正数对所有部位逐层按当前目标居中，0/null/省略维持整组中心和基础像素间距。
- 交付报告的 `Plane` 始终是医学状位，重复配置通过 `ConfigId` 和实际 `Path` 区分；
  带序号的 `output_plane` 仅是目录隔离名。
- nnUNet 返回数据集缺失时，失败报告动态说明模型 ID 和查找目录，不直接塞入整段堆栈；
  其他推理错误优先提取 stdout/stderr 中具体的异常，通用后台进程死亡提示不直接判定为
  内存不足；实际命令和原始输出进入默认开启的 `log/ErrorLog.txt`，仍遵守显式日志配置。
- 外部请求信息统一使用 `SlicePart`、`StudyType`、`ScanThickness`；扫描厚度是必填
  毫米数值，第二阶段按 `slice_part_config.json` 中包含上下边界的区间选择模型，
  不再使用扫描厚度档位枚举。
- `slice_part_config.json` 是切割部位启用状态、模型区间、定位区域、允许切法和范围扩展的
  唯一配置源；`nnuNet_config.json` 只保存 nnUNet 运行参数和路径。
- `dev build` 以 PyInstaller onedir 生成直接可执行的应用；JSON 位于程序旁的
  `src/config/`。nnUNet、PyTorch 和模型属于外部推理环境，外部命令由
  `nnUNet_predict_command` 指定，`nnUNet_python` 仅在需要指定外部解释器时使用。
- nnUNet 的预处理与导出进程数均默认 `1`，分别由 `num_processes_preprocessing` /
  `num_processes_segmentation_export` 传给 `-npp` / `-nps`，严格接受正整数；
  这些设置减少并发资源占用，不改变模型、TTA 或滑窗步长。
- 统一切割部位配置采用严格校验：未知字段、无效标签引用、未使用区域、重叠模型区间和
  切法与区域类型不一致都必须在启动时失败，不能静默回退。
- GDCM 写盘串行保护是跨模块安全约束，CT 成片和定位图写盘都应遵守。
- 第八阶段直接读取最终磁盘 DICOM 做发布门禁；数量、编号、UID、空间几何、
  层厚层间距或 Localizer 任一硬错误都必须阻止发布成功结果，并写入
  `Success=false` 的 `report.json`。
- Python 对所有可捕获异常和主动中断写失败报告；`kill -9`、原生崩溃和 OOM 等进程内
  无法执行清理的终止，由外部执行服务在子进程退出后检查并补写失败报告。
- 当前有效设计和代码注释一律使用八阶段职责与编号；只有 `archive/` 中的历史正文
  可以保留当时的六阶段说法。
