# 脊柱冠状位 CPR 设计

本文只描述当前冠状位 CPR。矢状位使用冠状位背景上的普通直线 MPR，不生成
`curved_stack`。

## 背景

当前阶段四、阶段五已经稳定支持 `plane_stack` 直线 MPR。腰椎区间切尝试用局部椎间隙几何生成斜横状位，但真实病例对终板、附件、骨刺和分割毛刺非常敏感，短期内不适合作为主要推进方向。

脊柱冠状位 CPR 使用过滤标注得到的椎体主体几何：按解剖顺序组织配置范围内
全部标注质心，首尾约束到首末椎体主体端面，中间质心链平滑，首尾端段保持直线，
最后按前后方向生成多张偏移 CPR 图像。矢状位不走 CPR，继续使用既有直线 MPR。

## 范围

本设计只覆盖第一版 CPR：

- 支持部位：颈椎、胸椎、腰椎。
- 支持状位：冠状位 CPR。
- 输出形态：一组偏移 CPR DICOM 图像序列。
- 曲线来源：自动从椎体 mask 和定位结果生成，不提供手动画线入口。
- 视野范围：覆盖目标椎体主体和两侧附件、骨刺等结构。

本设计不包含：

- 椎间盘区间精切。
- MIP/MinIP 等非平均厚层融合模式。
- 手动画线或交互式编辑。
- 基于神经网络的椎管中心线。

## 用户可见行为

当请求颈椎、胸椎或腰椎的冠状位时，系统生成 CPR 计划，而不是默认直线整切。矢状位保持现有直线 MPR，定位线画在冠状位背景上；横状位仍保持现有直线 MPR 或区间切策略。

输出目录保持现有按状位、窗位组织的结构，并在切割组中使用 `CPR`：

```text
矢状位/
  骨窗/
    1.dcm
    2.dcm
    ...
    Localizer.dcm
    Localizer.png   # debug 模式
冠状位/
  骨窗/
    1.dcm
    2.dcm
    ...
    Localizer.dcm
    Localizer.png   # debug 模式
```

矢状位直线图像顺序从患者左侧到右侧；冠状位 CPR 图像顺序沿患者前后方向
展开，中间一张经过脊柱中心曲线。两端图像覆盖目标标签的前后外缘，便于观察
椎体、椎弓根、横突、骨刺和其他附件位置。

CPR 标签由阶段三的 `resolved_cut_config` 决定。胸椎默认配置为 C7 至 L1，
因此 C7、T1–T12、L1 均进入 CPR 曲线和冠状位覆盖范围；腰椎及其他非颈椎
任务也按配置范围完整使用。只有颈椎固定排除 C1。

胸椎冠状位 CPR 的定位图使用矢状位背景，绘制配置目标段的全部 offset 中心线。
定位线复用实际 CPR 的曲线弧长重采样，并按
`curve_sample + offset_mm * offset_axis` 绘制；弯曲处的屏幕投影间距可以不等，
但每条线必须对应实际采集的一张 CPR 中心面。

Debug 输出保留当前仍用于排查和交付核对的内容：

- `slice_plans.json` 中的 CPR 曲线字段。
- debug 模式下，每个窗位目录的 `Localizer.dcm` 旁边额外写 `Localizer.png`，便于不用 ITK-SNAP 也能快速看定位线。
- warnings，包括缺失椎体、降级原因、标注质心回退和局部定位线连接信息。

阶段四默认不再写出 CPR NIfTI 调试总览，包括 `切片线_冠_CPR.nii.gz`、
`切片原始网格总览_冠_CPR.nii.gz`、`切片总览含原图_冠_CPR.nii.gz` 和
`十字中线_冠_CPR.nii.gz`。这些文件只属于前期研发核对，不作为阶段五输入；
需要看定位线时，以阶段五的 `Localizer.dcm`/`Localizer.png` 为准。

## 曲线生成

阶段四从阶段三定位结果读取两套几何：

- `spine_geometry.filtered_annotation_centroids`：由过滤标注得到的标注质心、局部头脚轴和主体端面中心，用于中心路径和曲率；
- `coords.*.bbox`：完整 nnUNet label 的包围盒，用于左右/前后偏移覆盖和降级
  范围；首尾白线长度由原始首末标签的沿线出口决定。

阶段四不再从完整 label 的全量质心计算 CPR 中心线。过滤标注和标注质心由阶段三生成，阶段四只负责使用标注质心生成计划。

每个椎体的主体 mask 在阶段三完成提取：

- 阶段三输出主体 mask 派生的物理质心；
- 阶段四读取标注质心生成中心线；
- 阶段四继续使用完整椎体 bbox（包括附件和骨刺）计算偏移覆盖范围；回正后的
  首尾端线从原始分割中搜索配置首末标签的沿线出口。

按本次整切配置确定椎体序列：

- 颈椎：展开配置范围后排除 C1；默认得到 C2 至 C7。
- 胸椎：默认配置 C7 至 L1，展开得到 C7、T1–T12、L1。
- 腰椎：使用实际配置范围，不固定为某一组标签。
- 旧定位结果缺少 `resolved_cut_config` 时，才使用部位默认列表兼容回退。

有效椎体点少于 3 个时，不生成 CPR，当前冠状位请求降级到直线 MPR。

有效标注质心达到 3 个后，在物理空间生成 CPR 基准路径：

- 每个椎体只贡献一个过滤标注质心。
- 阶段四先按头侧到足侧生成 CPR 锚点：中间为相邻椎体标注质心。
- 如果首末椎体存在主体四面几何，则路径锚点为“首端面中点 → 全部标注质心 → 末端面中点”；首尾端面约束来自过滤主体矢状投影轮廓四边形的四条大边：阶段四先找相邻质心线进入首末椎体的入射面，再取同一轴上的对侧大面中心，避免选到 PCA 外接矩形角点或斜边。旧结果缺少四面几何时，才回退到端部候选中心，不使用全量 bbox 角点。
- 全部标注质心始终作为不可移动的硬锚点；首尾端面只有越出局部正常弧线区间
  或回折时才修正到端部质心外延方向的 `0°` 射线，正常连续弧线保持不动。
- 反弧修正后保持“终端质心 → 当前端点”的方向，沿原始首末标签向外搜索到白线
  实际穿出标签的位置；不使用全量 bbox 极值拉长端线。
- 平滑后的 `curve_points` 还会用配置首末标签的原始体素做头足兜底：若终端原始
  标签仍有体素投影到首尾切线外侧，则只沿当前首尾切线继续延伸到投影外缘，
  并额外保留约一个体素量级的小安全垫；不改变中间质心和弧度。
- `SlicePlan.curve_points` 基于上述锚点生成圆滑加密中心线：全部质心硬锚点精确
  保留，中间质心链平滑，首尾端点到终端质心的区段保持直线，阶段五继续按曲线
  弧长生成最终 CPR 图像行。
- `local_superior_inferior_axis` 和 `local_superior_inferior_extent_mm` 暂存为后续局部定位线阶段的输入，本阶段不把它们展开为椎体内线段。
- CPR/区间切的范围可以继续使用全量标注 bbox，但范围端点不进入基准中心线。

## CPR 坐标系

每个曲线采样点都有一个局部坐标系：

- `tangent_dir`：沿曲线头脚方向。
- `left_right_dir`：患者左右方向，来自输入图像方向矩阵或既有解剖坐标。
- `anterior_posterior_dir`：患者前后方向，来自输入图像方向矩阵或由局部坐标正交构造。

CPR 输出图像固定为常规冠状位阅读方向：

- 图像行方向（左到右）沿患者左右方向。
- 图像列方向（上到下）沿曲线从头侧到足侧的弧长方向。
- 每个像素的三维物理点由
  `center_curve_point + offset_mm * anterior_posterior_dir + horizontal_mm * row_dir`
  得到，其中 `row_dir` 由局部头脚切线与前后偏移轴叉乘得到。

这样输出上下保持头脚一致，左右表达患者左右方向，避免图像随曲线局部扭转。

冠状位 CPR 按 `anterior_posterior_dir` 生成偏移曲面，图像横向覆盖左右方向：

- 自动计算配置范围内原始椎体 label 体素相对中心曲线的前后最小、最大偏移。
- 按请求的 `slice_thickness` 和 `slice_spacing` 生成多条厚层 CPR 偏移曲面；
  两侧张数可以不同，最外层必须不少包原始体素外缘。
- `offsets_mm` 必须包含 `0`，保证至少一张经过中心曲线。
- 当前矢状位 Localizer 只绘制全部 offset 中心曲线；其曲线采样点和 offset
  必须与实际 CPR 重建一致，不以屏幕等距为目标。

## 阶段四协议

新增 `geometry_type = "curved_stack"`。

第一版 CPR plan 至少包含：

```json
{
  "geometry_type": "curved_stack",
  "curve_points": [{"x": 0, "y": 0, "z": 0}],
  "curve_spacing_mm": 1.0,
  "offset_axis": {"x": 1, "y": 0, "z": 0},
  "offsets_mm": [-20, -15, -10, -5, 0, 5, 10, 15, 20],
  "extent_mm": {"width": 120, "height": 300},
  "output_spacing_mm": {"x": 1, "y": 1, "z": 0},
  "slice_thickness": 3.0,
  "slice_spacing": 5.0
}
```

字段含义：

- `curve_points`：由修正后的过滤主体端面约束和全部过滤标注质心连接出的圆滑加密中心线，按头脚顺序排列，并精确保留全部质心硬锚点。
- `curve_spacing_mm`：曲线弧长方向输出采样间距。
- `offset_axis`：冠状位 CPR 的患者前后偏移方向单位向量。
- `offsets_mm`：每张 CPR 图相对中心曲线的偏移。
- `extent_mm.width`：冠状位输出图沿患者左右方向的覆盖范围。
- `extent_mm.height`：输出图头脚方向弧长覆盖。

`SlicePlan.slices` 对 `curved_stack` 不再表示普通平面切片，而表示每个前后偏移
CPR 图的索引和偏移中心。为避免误用，阶段五必须按 `geometry_type` 分发到专用
`CurvedStackResampler`。

`curved_stack` 的 `localizer_plane` 固定为 `矢状位`。阶段五 DICOM Localizer
直接绘制实际 CPR 使用的弧长重采样中心曲线，再按每个 `offset_mm` 沿
`offset_axis` 平移，而不是计算普通切片平面与定位面的交线；不额外绘制厚层边界。
阶段四默认跳过
CPR NIfTI 调试总览，只保留计划 JSON。普通 `plane_stack` 仍沿用平面交线逻辑。

## 阶段五重采样

新增 `CurvedStackResampler`。

它对每个 `offset_mm` 生成一张 CPR 图：

1. 将中心曲线按弧长重采样成均匀点。
2. 对每个曲线点构造局部采样方向。
3. 沿输出图每个像素计算其三维物理坐标。
4. 使用 SimpleITK 线性插值从原始 CT 采样 HU。
5. 输出 size 为 `(columns, rows, 1)` 的 2D 图像。

当前 CPR 已支持厚层平均。阶段四按原始配置标签体素外缘、`slice_thickness` 和
`slice_spacing` 计算前后 offset 张数；阶段五对每个 offset 的厚层 slab 做算术
平均，DICOM 元数据继续写入请求层厚和层间距。MIP/MinIP 等融合模式仍作为后续
显式配置处理。

## 降级和错误处理

以下情况把当前冠状位请求降级到直线 MPR，并写 warning：

- 有效椎体点少于 3 个。
- 目标分割图缺失。
- 目标 label id 缺失。
- 曲线长度过短。
- 曲线拟合失败。

以下情况可以继续生成 CPR，但写 warning：

- 中间椎体缺失。
- 左右覆盖范围异常大，经过上限裁剪。
- 四棱柱不可用但过滤主体质心可用时，退回过滤主体质心。
- 只有旧定位结果完全没有过滤标注契约时，才兼容使用全量质心。

CPR 生成失败时，不应输出半成品 DICOM 到正式目录。

## 测试策略

阶段四测试：

- 三个以上椎体质心生成 `curved_stack`。
- 颈椎、胸椎、腰椎均能按配置选择正确椎体序列。
- 缺少中间椎体仍能生成 CPR 并写 warning。
- 少于三个椎体时降级直线整切。
- 左右 offset 覆盖完整椎体 mask 投影范围。

阶段五测试：

- `CurvedStackResampler` 对直线曲线输出应等价于普通矢状位采样。
- 弯曲曲线输出中，曲线弧长方向像素随曲线连续采样。
- 多个 offset 生成独立 DICOM 文件，顺序从左到右。
- `curved_stack` 的 DICOM Localizer 应在矢状位背景上画出基准弯曲线，不能退化
  成斜直线。
- 未知或缺字段的 `curved_stack` plan 明确报错。

集成测试：

- 腰椎请求横状位、矢状位和冠状位时，横状位继续使用当前策略、矢状位生成
  直线 MPR、冠状位生成 CPR。
- 颈椎、胸椎矢状位生成直线 MPR、冠状位生成 CPR，并保留现有横状位行为。
- 阶段五 CPR Localizer 在 ITK-SNAP 中应显示目标椎体段的弯曲中心线。

## 迁移策略

区间切相关代码先冻结，不继续扩大改动。CPR 实现完成后再决定：

- 保留区间切作为实验能力。
- 回退区间切到 bbox 简单版本。
- 或将区间切依赖 CPR 中心曲线重新设计。

CPR v1 不要求清理区间切代码，避免误删已有调试资产和未提交工作。
