# 文档与代码一致性审阅设计

## 背景

项目文档同时包含当前规则、实施过程和历史方案。脊柱 CPR 近期连续调整后，
部分旧设计仍写着“胸椎只使用 T1–T12，C7/L1 不参与 CPR”，但当前代码已经
改为按阶段三解析后的整切配置展开标签：胸椎默认配置为 C7 至 L1，因此 C7、
T1–T12 和 L1 全部参与 CPR。旧文档没有被明确隔离，导致阅读时把历史规则误判
为当前行为。

本次工作以当前代码、配置和测试为事实源，完整审阅仓库内 Markdown 文档，修正
当前有效文档并隔离历史内容，同时增加自动检查，防止关键规则再次发生文档回退。

## 目标

- 审阅仓库内全部 Markdown 文档，明确每份文档属于当前规则、当前计划或历史记录。
- 以运行时代码和测试为准修正当前有效文档，不根据旧方案反推代码行为。
- 统一脊柱定位、标签范围、CPR 状位、质心和端点规则。
- 已完成计划移入 `archive/plans/`，顶层 `plans/` 只保留未完成计划。
- 顶层 `specs/` 只保留旧路径说明；有效设计进入 `architecture/` 或对应模块。
- 历史文档保留原始实施过程，但必须能明确识别为历史，不再作为当前规则入口。
- 增加自动文档一致性检查，覆盖本次暴露出的关键冲突。

## 非目标

- 不改变脊柱定位、CPR 规划、MPR 重建或 DICOM 输出代码行为。
- 不为了统一措辞重写全部历史实施步骤。
- 不把尚未实现的回正、厚层 CPR、局部椎体定位线等能力描述成当前能力。
- 不修改与本次任务无关的用户工作区文件。

## 事实源优先级

出现冲突时按以下顺序判断当前行为：

1. 运行时代码和实际配置；
2. 能直接验证该行为的自动测试；
3. `architecture/`、`modules/*/README.md` 和当前有效设计；
4. `plans/` 中尚未完成的实施计划；
5. `archive/` 中的历史计划和旧设计。

历史文档只能解释“当时为什么这样做”，不能覆盖当前代码事实。

## 当前脊柱行为契约

### 标签范围

- 阶段三把脊柱整切配置的首尾标签按统一解剖顺序展开。
- 胸椎默认配置为 C7 至 L1，当前 CPR 使用 C7、T1–T12、L1。
- 腰椎和其他非颈椎脊柱任务均按实际配置范围使用，不额外删除首尾标签。
- 颈椎同样按配置范围展开，但 CPR 和过滤标注质心固定排除 C1；C1 仍保留在
  全量定位和切图覆盖范围。
- 只有旧定位结果缺少 `resolved_cut_config` 时，CPR 才使用部位默认标签列表
  作为兼容回退；正常流水线必须以解析后的配置为准。

### 定位与质心

- 全量 `coords` 继续负责定位、bbox 和覆盖范围。
- 过滤主体及其规则化四棱柱负责 CPR 中间质心和端面几何。
- 四棱柱矢状拟合只使用 LR 支撑合格投影中的最大二维连通块，避免独立碎渣
  拉歪四边形和质心。
- 四棱柱可用时优先使用其栅格 Mask 质心；失败时按现有兼容规则回退到过滤
  主体质心，不回退到全量 label 质心。

### CPR 与状位

- 脊柱冠状位使用 `curved_stack` CPR。
- 脊柱矢状位使用现有直线 `plane_stack` MPR，不走 CPR。
- CPR 路径使用配置范围内所有可用过滤标注/四棱柱质心。
- 正常连续弧线上的首尾端面保持不动；只有反弧或回折时才投影到端部质心
  外延方向。
- 回正后的首尾端线保持方向，并沿原始分割中的首末标签延伸到白线穿出标签的
  实际出口，不使用全量 bbox 极值决定长度。

## 文档分类与处理

### 当前有效文档

包括根 `README.md`、`docs/superpowers/README.md`、`architecture/`、
`modules/*/README.md` 和模块当前设计。它们必须与代码一致，并优先写当前行为，
不保留会误导当前使用者的旧结论。

### 当前计划

`docs/superpowers/plans/` 只允许存在正在执行或即将执行的计划。全部任务已经完成
的计划必须移入 `archive/plans/`。

### 历史文档

`archive/plans/` 和 `archive/specs_old/` 保留实施历史。归档目录 README 必须
明确声明历史内容可能与当前代码不同，并指向当前文档入口。对包含高风险冲突、
且可能通过搜索结果被直接打开的历史文档，在顶部增加替代关系说明，不重写其正文。

### 旧路径

`docs/superpowers/specs/` 只保留 README。残留的有效设计应移入相应模块；被替代
的设计移入 `archive/specs_old/` 并注明当前替代文件。

## 自动防回退检查

新增文档一致性测试，至少验证：

- 胸椎当前配置首尾是 C7 和 L1；
- 按解析后配置生成的 CPR 标签包含 C7、T1–T12 和 L1；
- 颈椎 CPR 标签排除 C1；
- 当前文档中不存在“胸椎只使用 T1–T12”“C7/L1 不进入 CPR”“冠状位 CPR
  尚未实现”等已知过时结论；
- `plans/` 中不存在所有任务均已完成的计划；
- `specs/` 中不再残留具体设计；
- 当前文档的相对 Markdown 链接指向存在的文件。

检查只扫描当前有效文档；归档正文允许保留历史规则，但归档入口必须声明其历史属性。

## 审阅与验证

1. 枚举全部 Markdown 文件并按目录分类。
2. 搜索标签范围、C1、C7/L1、T1–T12、CPR 状位、平滑、端点、bbox、回正和
   “当前/尚未实现”等关键词。
3. 对每条当前行为描述定位到代码、配置或测试依据。
4. 修正当前文档，移动完成计划和残留规范，补齐归档说明。
5. 运行文档一致性测试、Markdown 链接检查、`git diff --check` 和全量测试。
6. 只暂存本次文档、检查代码和相关测试，确认不包含用户无关改动后提交。

## 验收标准

1. 从任一当前文档入口读取脊柱规则，都能得到相同的配置驱动标签范围。
2. 胸椎 C7/L1 是否参与 CPR 的描述与代码和测试一致。
3. 当前文档不再声称冠状位 CPR 尚未实现，也不把矢状位描述为 CPR。
4. 完成计划和旧规范不会继续出现在当前入口目录。
5. 自动检查能在重新写入上述已知过时结论时失败。
6. 全量测试和文档检查通过，提交不包含无关工作区文件。
